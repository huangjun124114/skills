## 一、12 项自检指标（1-5 分，分越高 = 越痛）

打分基准：1 分 = 完全不痛；5 分 = 极痛。5 级量表：完全不痛(1) / 轻度疼痛(2) / 中度疼痛(3) / 较痛(4) / 极痛(5)。

### 品 (Product) — 根基 / 价值载体（满分 15）
| 编号 | 指标 | 判定要点 |
|------|------|----------|
| P1 | 竞争力弱 | 缺乏壁垒，同质化严重，只能拼价格 |
| P2 | 交付无力 | 口碑差，退货率高或复购率极低 |
| P3 | 迭代滞后 | 新品上市成功率低，跟不上市场节奏 |

### 牌 (Branding) — 资产 / 心智溢价（满分 15）
| 编号 | 指标 | 判定要点 |
|------|------|----------|
| B1 | 面目模糊 | 定位不清，消费者说不出"你是谁" |
| B2 | 缺乏溢价 | 势能弱，一涨价客户就跑，无议价权 |
| B3 | 资产流失 | 有知名度无美誉度，甚至负面缠身 |

### 营 (Marketing) — 流量 / 获客手段（满分 15）
| 编号 | 指标 | 判定要点 |
|------|------|----------|
| M1 | 流量枯竭 | 依赖单一渠道，红利见顶后无以为继 |
| M2 | 内容平庸 | 只叫卖不传播，停投流就没声量 |
| M3 | 效率低下 | 获客成本(CAC)飙升，ROI 持续走低 |

### 销 (Sales) — 转化 / 临门一脚（满分 15）
| 编号 | 指标 | 判定要点 |
|------|------|----------|
| S1 | 承接漏斗 | 有流量无转化，销售/客服接不住线索 |
| S2 | 渠道阻滞 | 经销商动力不足，甚至窜货乱价 |
| S3 | 团队内耗 | 销售缺乏狼性，与市场部互相甩锅 |

## 二、计分规则与总体诊断阈值

- 总分 = 12 项之和，满分 60。
- 维度小计：品 = P1+P2+P3；牌 = B1+B2+B3；营 = M1+M2+M3；销 = S1+S2+S3，各满分 15。
- **反直觉提示**：分数越高代表问题越严重（能力越差）。诊断书与矩阵中务必用"疼痛度"措辞，避免把高分误读为"表现好"。

| 总分 | 评级 | 含义 | 基调 |
|------|------|------|------|
| > 45 | 危重期 | 全身衰竭 | 建议止损或刮骨疗毒 |
| 30-45 | 亚健康 | 带病奔跑，功能性紊乱 | 需系统调理 |
| < 30 | 健康期 | 体质强健 | 重点在寻找新增长点 |

维度诊断：找出小计最高的维度，标注其性质——
- 品最高 → 根基问题
- 牌最高 → 灵魂问题
- 营最高 → 手段问题
- 销最高 → 转化问题

### 最痛维度同分裁决

必须锁定一个访谈入口，不得同时对多个维度展开浅层追问。维度小计并列时依次比较：

1. 维度内单项最高分；
2. 维度内 `4-5 分` 项的数量；
3. 若仍并列，询问用户："这几个维度中，哪一个对你当前最重要的经营目标伤害最大？请只选一个。"

锁定维度后，以该维度内最高分指标作为表象入口。指标并列时，用同一条"对当前经营目标伤害最大"规则裁决。根因允许跨维度，不要把入口误当结论。

## 三、深度归因：多轮根因访谈（Phase 4）

### 3.1 候选归因地图

- **品 / 牌**的高疼痛通常指向内伤 / 资产亏空，候选原因包括产品价值不成立、定位与客户心智错位、交付不一致、品牌承诺缺乏事实支撑。
- **营 / 销**的高疼痛通常指向外伤 / 效率低下，候选原因包括渠道结构、内容与人群错配、漏斗断点、销售流程、权责与激励失配。
- 以上只是生成假设的地图，不是根因结论。外伤可能由内伤引发，内伤也可能被组织流程或资源配置长期放大。

系统根因可从以下层级定位：战略取舍 / 客户与价值假设 / 产品与交付 / 流程与决策权 / 组织与激励 / 人员能力 / 资源与技术 / 数据与反馈机制 / 外部约束。优先寻找组织可干预、能够解释问题反复发生的上游因素。

### 3.2 至少三轮的逐层追问

每轮只问一个主问题。必须等用户回答后，引用回答中的事实生成下一问；不得预先把三轮问题一起抛给用户。

#### 第 1 轮：钉住事实——它到底怎样发生

目标：把"我觉得有问题"变成可观察的事件、行为和结果。

基础问法：
> 请还原最近一次【最高分指标】真实发生的例子：当时面对什么客户/场景，谁做了什么，最后出现了什么可观察结果？如果有数字，请给出最关键的一个。

按维度选取最贴近入口的追问角度：

- 品：最近一次客户流失、退货、差评或新品失败；关注客户原话与产品/交付事实。
- 牌：最近一次客户无法识别差异、拒绝溢价或产生负面评价；关注客户原话与选择行为。
- 营：最近一次活动、内容或渠道投放；关注曝光、点击、线索、CAC、ROI 中最先恶化的数据。
- 销：最近一次线索、经销商或订单流失；关注进入哪一步、由谁跟进、在哪一步中断。

只有观点没有事件、角色、行为或结果时，回答无效，留在本轮追问例子。

#### 第 2 轮：找到断点——哪一步最先偏离

目标：从结果倒推直接机制，不停留在"效果差"。

基础问法：
> 你提到【复述第 1 轮的具体事实】。从【相关业务链条起点】到【结果】的几步里，最早出现偏差的是哪一步？当时哪项具体决策或动作让后续结果开始恶化？

可用业务链条：

- 品：需求洞察 → 产品定义 → 研发/采购 → 交付 → 售后反馈。
- 牌：目标人群 → 定位 → 价值承诺 → 触点表达 → 客户选择/付费。
- 营：人群 → 内容/素材 → 分发 → 点击 → 线索 → 成本/回报。
- 销：线索进入 → 资格判断 → 跟进 → 方案/报价 → 成交 → 复购。

若用户只给出"能力不行、执行不到位"等标签，追问："具体是哪一个角色，在什么节点，没有做出哪项本应发生的行为？"

#### 第 3 轮：追到维持机制——为什么它会重复发生

目标：找到让直接断点长期存在的系统因素，而不是再描述一次症状。

基础问法：
> 既然【复述第 2 轮的断点】已经造成【结果】，它为什么到现在仍会重复发生？真正阻止团队修正它的机制是什么？请选最接近的一项并给一个事实：战略优先级、价值假设、流程/权责、激励、能力、资源/技术、数据反馈、外部约束，或其他。

若用户回答一个抽象标签，继续拆解：

- "市场不好" → 同类企业是否都同幅度恶化？哪些内部变量能解释差异？
- "预算不足" → 哪项资源配置决定造成不足？增加预算后，已知断点为何会消失？
- "团队不行" → 缺的是哪项可观察行为？由招聘、培训、流程、授权还是激励造成？
- "执行不到位" → 谁在何节点为何选择不执行？不执行的收益或执行的阻力是什么？
- "客户不认可" → 不认可哪项承诺？是产品事实不成立，还是表达/触达/证据不足？

#### 第 4 轮及以后：反证与补洞

满足任一情况就继续追问，不得为了赶流程强行收敛：

- 关键陈述没有实例、数据或可观察行为；
- 因果顺序不清，所谓根因可能晚于问题出现；
- 存在同样条件下却没有出现问题的反例；
- 候选原因无法解释问题为何长期反复；
- 候选原因完全不可干预，却尚未排除内部可控因素；
- 仍存在两个以上同样合理的竞争解释。

优先使用以下单问法：

- 反事实："如果明天彻底解决【候选根因】，在其他条件不变时，哪个关键指标会先改善？为什么？"
- 对照："有没有在同样市场/预算条件下表现更好的团队、渠道或产品？它们唯一关键差异是什么？"
- 时间线："这个原因是在症状出现之前就存在，还是症状出现后才被发现？"
- 证据："目前最能支持这条判断的事实是什么？有什么事实会推翻它？"

### 3.3 根因质量门槛

只有以下条件**全部满足**，才可以输出根因并请求用户确认：

1. 已收到至少 3 个有效回答；事实含事件/角色/行为/结果，空泛回答不计数。
2. 因果链至少包含：表象问题 → 直接断点 → 维持机制 → 系统根因。
3. 根因在时间上先于表象，且有清楚的中间机制连接二者。
4. 根因能解释问题为何重复发生，并能解释最痛维度的关键业务结果。
5. 至少有一项事实支持，并完成一次反事实或对照检查；若只靠推测，标记"待验证"并继续追问。
6. 根因是可被改变的具体系统因素；若最终判断为外部约束，必须说明已排除哪些内部可控因素。

根因表述禁止使用无法直接行动的标签，如"大环境差、预算少、团队弱、执行差、品牌不行"。改写为：

> 由于【可改变的系统因素】，在【触发条件】下，【关键角色/流程】会反复做出【行为或决策】，经由【直接机制】造成【表象及业务结果】。

### 3.4 收敛输出与用户确认

按以下结构输出，随后只问确认问题：

1. **最痛维度与表象入口**：维度小计、最高分指标。
2. **事实证据**：仅列用户提供的事件、原话或数据。
3. **因果链**：表象问题 → 直接断点 → 维持机制 → 系统根因。
4. **诊断判断**：根因陈述 + 置信度（高/中/低）+ 待验证项。
5. **确认**："这条因果链与实际情况相符吗？请确认或指出哪一环不成立。"

用户确认后，Phase 5 的三条行动必须逐一映射到因果树节点，优先改变系统根因及维持机制；不能只针对表象做加投放、加人或泛化培训。

## 四、品牌势能-营销势能矩阵（Phase 5 判决）

### 计算逻辑
- **品牌疼痛分 B** = 品维度分 + 牌维度分（满分 30）。B 越低 = 品牌势能越强。
- **营销疼痛分 M** = 营维度分 + 销维度分（满分 30）。M 越低 = 营销势能越强。
- 因"高分=高痛点"，低疼痛分对应高势能。
- 图上横坐标标题固定为"营销势能强弱"，左弱右强；纵坐标标题固定为"品牌势能强弱"，下弱上强。

### 四象限判定规则

| 象限 | 条件 | 含义 | 战略边界 | 颜色 |
|------|------|------|----------|------|
| 明星象限（右上） | B 低 + M 低 | 品牌势能强 + 营销势能强，有面子有里子 | 护城河 / 防守 | 绿 |
| 沉睡象限（左上） | B 低 + M 高 | 品牌势能强 + 营销势能弱，叫好不叫座（阻塞） | 营销激活 / 换血 | 黄 |
| 裸奔象限（右下） | B 高 + M 低 | 品牌势能弱 + 营销势能强，有销量没灵魂（虚胖） | 品牌沉淀 / 补课 | 黄 |
| 濒危象限（左下） | B 高 + M 高 | 品牌势能弱 + 营销势能弱，没产品没销量（重症） | 彻底重组 / 关停 | 红 |

> 象限划分阈值：以各自满分 30 的中位 15 为界。疼痛分低于 15 = 该势能强；高于 15 = 该势能弱。绘图时右上角必须是明星象限。

### SVG 坐标校验

使用 `viewBox="0 0 400 400"`，SVG 左上角为 `(0,0)`：

- `x = 400 - (M/30)*400`：M 越低，x 越大，营销势能越强、越靠右。
- `y = (B/30)*400`：B 越低，y 越小，品牌势能越强、越靠上。
- 右上明星、左上沉睡、右下裸奔、左下濒危。

出图前用四个极值进行自检：`B=0,M=0` 必须落在右上（明星）；`B=0,M=30` 左上（沉睡）；`B=30,M=0` 右下（裸奔）；`B=30,M=30` 左下（濒危）。任一不符就修正坐标，不得输出。

### 各象限战略边界

象限只用于校准轻重缓急，**不能直接当作行动计划**。最终行动必须从已经确认的根因倒推，并结合企业现有角色、资源和业务节奏具体化。

**明星象限（护城河/防守）**
- 巩固产品壁垒：加大研发与专利护城河
- 放大品牌资产：将美誉度转化为溢价与复购
- 警惕 complacency：建立创新第二曲线，防止被颠覆

**裸奔象限（品牌沉淀/补课）**
- 停止单纯买量，把预算向品牌内容倾斜
- 重新梳理品牌定位，讲清"我是谁、为何不同"
- 用产品迭代支撑品牌叙事，避免空心化

**沉睡象限（营销激活/换血）**
- 诊断渠道阻塞点：是承接漏斗还是经销商动力
- 内容从"叫卖"升级为"传播"，建立内容资产
- 销售团队换血或激励机制重构，打通临门一脚

**濒危象限（彻底重组/关停）**
- 止血优先：砍掉持续失血的业务线/渠道
- 评估是否有抢救价值，否则果断关停并转
- 若抢救：从"品"的根本做起，先有能打的产品再谈其他

## 五、根因因果树规范

### 5.1 主干结构

只使用 Phase 4 已经确认的信息搭建主干。**视觉布局固定为纵向追因**，从表象往下挖到根因：

`S1 最痛表象`  
`↓ 为什么会发生？`  
`D1 直接断点`  
`↓ 为什么没有被修正？`  
`M1 维持机制`  
`↓ 为什么机制会长期存在？`  
`RC1 系统根因`

向下箭头表示诊断时的追问方向；真实因果作用从最下方的 RC1 向上经过 M1、D1，最终造成 S1。`R1 业务结果`放入 S1 卡片的结果说明区域或作为 S1 的紧邻辅助卡，不进入纵向主干。

- `RC1`：组织可干预、能解释问题反复发生的系统因素。
- `M1`：让问题长期无法被修正的流程、权责、激励、能力或反馈机制。
- `D1`：业务链条中最早出现偏差的具体动作或决策。
- `S1`：评分和访谈指向的最痛表象。
- `R1`：可观察的经营后果，如流失、退货、转化下降、CAC 上升或复购下降；在视觉上附属于 S1。

必要时最多增加 2 个分支：

- `A1/A2 放大因素`：会加重问题，但单独存在不足以造成结果。
- `V1 待验证因素`：存在合理怀疑但证据尚不足，必须使用虚线并写明验证方法。

主树最多 7 个节点。S1、D1、M1、RC1 必须在同一条竖直中轴线上，根因位于最下方；分支只能从对应节点向左右短距离展开。没有用户事实或合理诊断依据时不要添加分支，宁可保持一条清楚的主干。

### 5.2 证据状态

每个节点必须标注一种状态：

- **用户事实**：用户提供了事件、原话、数字或可观察行为；使用实线。
- **诊断推断**：由多轮回答推导且经用户确认；使用实线，并注明推断依据。
- **待验证**：尚缺数据或存在竞争解释；使用灰色虚线，不能写成既定事实。

因果树下方列出节点证据表：`节点编号｜判断｜证据/用户原话｜状态｜如何验证`。90 天行动必须引用节点编号，形成“诊断—行动”闭环。

## 六、90 天改善行动计划规范

### 6.1 设计顺序

先写清改变机制，再写动作：

`要改变的节点 → 希望发生的新行为/新机制 → 最先变化的领先指标 → 最终业务结果`

只给 3 条行动，按下列节奏递进：

1. **行动一｜第 1-30 天：止血与校准**  
   直接干预 `RC1/M1`，同时补齐必要基线。前 7 天必须产生首个可检查交付物，不能把整月用来调研、开会或写方案。
2. **行动二｜第 31-60 天：小范围验证**  
   选择一个产品、渠道、区域、客户群或销售小组做试点，用领先指标判断新机制是否有效；未达阈值先迭代，不直接全面铺开。
3. **行动三｜第 61-90 天：固化与放大**  
   只把已经被试点证明有效的做法写进 SOP、考核或固定节奏，再扩到第二个场景；若试点失败，写明停止或回滚条件。

### 6.2 每条行动卡的必填字段

每条行动必须包含以下内容，缺一项就不算可执行：

| 字段 | 写法要求 |
|------|----------|
| 行动名称 | 使用“动词 + 明确对象”，如“重做流失客户复盘表”，不能写“提升品牌力” |
| 作用节点 | 引用因果树编号，如 `RC1 + M1`，说明为什么先动它 |
| 负责人 | 指定一个最终负责的角色，禁止写“相关部门/团队共同负责” |
| 起止与频次 | 写明第几天开始、何时完成、每周或每日频次 |
| 执行步骤 | 2-4 个可以照做的步骤，每步有对象、数量或截止时间 |
| 交付物 | 可检查的文件、名单、页面、脚本、SOP、看板或试点结果 |
| 领先指标 | 最早能证明机制改变的 1 个指标；说明基线来源与查看频次 |
| 验收标准 | 写清到期时达到什么状态算完成，未达到时如何调整/停止 |
| 最低资源 | 所需角色、工时、预算或工具；优先使用现有团队和低成本方案 |

### 6.3 接地气规则

- 每条行动至少出现一个明确数量、频次、样本范围或完成日期。
- 优先“小样本、短周期、能复盘”的试点；除非证据充分，不把招聘、换系统、大投放当作第一动作。
- 缺少基线时，在行动一中安排第 7 天前完成测量。不得编造历史数据；目标写成“建议目标”或“待基线后确认”。
- 指标最多使用 1 个领先指标 + 1 个结果指标，避免堆砌 KPI。
- 负责人只设一个最终 owner，可以列协作角色，但不能用“大家一起做”逃避责任。
- 每条行动都要回答：“下一个工作日具体先做什么？”若不能回答，继续拆小。
- 禁止使用没有动作对象的空话：加强、提升、优化、重视、赋能、打造、持续关注。

示例：

- **粗糙**：加强用户洞察，优化品牌定位。
- **可执行**：第 1-10 天由品牌负责人访谈 8 名近 90 天流失客户，按“购买任务/拒绝理由/替代品牌/可接受价格”记录原话；第 12 天交付一页定位假设，选择 2 个版本在同一渠道各测试不少于 100 次有效访问。访谈数和测试量属于建议值，实际应按企业体量调整并明确标注。

### 6.4 行动与象限的关系

象限只约束资源取向，不替代根因设计：

- 明星：避免大改，以防守核心资产和验证第二曲线为主。
- 裸奔：优先补产品事实、定位证据和品牌资产，避免继续单纯买量。
- 沉睡：优先疏通渠道、内容或销售断点，用小试点恢复营销势能。
- 濒危：先停损和验证抢救价值；未经验证，不追加大额预算。

## 七、《品牌现状诊断书》交付清单

Markdown 与 HTML 两版必须包含相同结论：

1. 综合得分与评级（危重/亚健康/健康）。
2. 四维度得分雷达（品/牌/营/销各小计）。
3. 核心病灶分析（哪个维度是“大动脉出血点”）。
4. 根因因果树：节点编号、方向、证据状态及节点证据表。
5. 品牌势能-营销势能矩阵定位：营销势能强在右、品牌势能强在上；明星在右上、沉睡在左上、裸奔在右下、濒危在左下，作为战略边界而非直接行动答案。
6. 90 天改善行动计划：严格 3 条行动，完整填写行动卡字段并映射因果树节点。
7. 夏日老师寄语："体检是为了更好的出发，先解决最痛的那个点"。
