## 📖 项目简介

这是一个**通用内容自动化运营框架**，专为需要高频内容产出但人力资源有限的团队设计。通过状态机驱动的多流水线架构，实现从采集、选题、创作、润色到审批、发布的全流程自动化。

### 核心价值

- ⚡ **效率提升 85%**：日常运营从 20h/周 降至 3-5h/周
- 🎯 **质量持续提升**：固定专家池 + 自进化机制，越用越专业
- 👁️ **全流程可视**：每条流水线的每个阶段精确记录，随时可查
- 🔄 **数据驱动优化**：发布 → 效果追踪 → 复盘 → 自动优化专家 Skill

### 适用场景

- 需要每日产出多篇内容（公众号、知乎、头条等）
- 运营团队人力有限（1-2人），需 AI 承担 80%+ 工作量
- 需要多平台同步发布，内容风格统一
- 希望内容质量持续提升（基于效果数据优化）

### 不适用场景

- 纯人工协作的内容团队
- 不需要自动化调度的单次内容创作
- 没有 WorkBuddy 桌面智能体的环境

## ✨ 核心特性

### 1. 状态机驱动调度（非固定时间触发）

**传统定时调度的问题**：
```
❌ 09:00 触发选题 → 09:30 触发创作（但选题还没完成）
❌ 等待时间浪费，或者任务被打断
```

**本框架的解决方案**：
```
✅ 选题完成 → 立即触发创作
✅ 创作完成 → 立即触发润色
✅ 上一阶段完成 = 下一阶段开始
```

### 2. 多流水线并行

每天自动创建一条独立流水线，支持临时加开：

```
2026-07-31:
  ├─ PL-20260731-001  [政策类]  ✅ 已完成
  ├─ PL-20260731-002  [行业类]  🔄 创作中
  └─ PL-20260731-003  [产品类]  ⏳ 选题确认

2026-08-01:
  ├─ PL-20260801-001  [行业类]  🔄 润色中
  └─ PL-20260801-002  [痛点类]  ⏳ 新创建
```

### 3. 固定专家池（越用越专业）

5 个专家角色持续迭代，积累经验：

| 专家角色 | 负责内容类型 | 核心能力 |
|---------|------------|---------|
| 📋 **政策解读者** | 政策解读、法规分析 | 政策拆解 → 影响分析 → 建议 |
| 📰 **行业观察家** | 行业动态、市场趋势 | 数据整合 → 趋势判断 → 洞察 |
| 🚀 **产品布道师** | 产品功能、体验升级 | 功能翻译 → 场景演示 → 价值传递 |
| 💡 **痛点猎手** | 场景痛点、客户故事 | 故事构建 → 共情触发 → 方案植入 |
| 🔍 **内容打磨师** | 所有类型的润色 + 合规 | 去 AI 味 → 事实核查 → 品牌一致性 |

每个专家都有自己的 Skill 文件，记录写作模板、历史案例、迭代日志。**用得越多，越懂你的品牌风格。**

### 4. 自进化机制

系统会自动学习、自动优化：

```
每发布 5 篇  → 微进化（优化最有效的专家模板）
每发布 10 篇 → 中进化（审视选题策略 + 排期规则）
每发布 30 篇 → 大进化（全面审视架构、专家池、调度规则）
```

**进化边界**：
- ✅ **可自动更新**：专家模板、选题策略、排期规则、通知模板
- ⚠️ **需用户确认**：新增/删除专家角色、修改调度频率
- 🚫 **不可更新**：架构设计、状态机定义、流水线规范

### 5. 全流程可视化

每条流水线的每个阶段都精确记录：

```markdown
## 流水线状态

| 阶段 | 状态 | 开始时间 | 结束时间 | 耗时 |
|------|------|----------|----------|------|
| 选题 | ✅ 完成 | 08:00 | 08:15 | 15m |
| 创作 | ✅ 完成 | 08:15 | 09:30 | 75m |
| 润色 | 🔄 进行中 | 09:30 | - | - |
| 审批 | ⏳ 待处理 | - | - | - |
```

## 🏗️ 架构设计

### 三层调度架构

```
┌─────────────────────────────────────────────────────────┐
│  L0 · 每日写作计划调度器                                  │
│  触发时间: 工作日 08:00 + 手动触发                        │
│  职责: 创建流水线实例，分配今日写作任务                    │
└────────────────┬────────────────────────────────────────┘
                 │ 创建流水线
                 ▼
┌─────────────────────────────────────────────────────────┐
│  L1 · 流水线调度器                                       │
│  扫描频率: 每小时 1 次                                    │
│  职责: 按状态机规则推进流水线                             │
│  规则: 上一阶段完成 → 立即触发下一阶段                    │
└────────────────┬────────────────────────────────────────┘
                 │ 按内容类型匹配
                 ▼
┌─────────────────────────────────────────────────────────┐
│  L2 · 固定专家池                                        │
│  5 个专家角色: 政策解读 / 行业观察 / 产品布道 /            │
│              痛点猎手 / 内容打磨                          │
│  职责: 执行创作/润色，积累案例，迭代 Skill               │
└─────────────────────────────────────────────────────────┘
```

### 流水线状态机（12 阶段）

```
新创建 → 选题就绪 → 选题确认 → 创作中 → 草稿完成 → 润色中 
  ↓         ↓         ↓         ↓         ↓         ↓
润色完成 → 审批中 → 已完成 → 已归档
```

每个状态转换都记录精确时间戳，形成完整的执行链路。

## 🚀 快速开始

### 前置条件

- WorkBuddy 桌面智能体（核心引擎）
- IMA 知识库或本地文件系统（存储素材和稿件）
- 企微 Bot / 邮件 / 钉钉（通知渠道，三选一）
- 品牌上下文资料（产品介绍、参考案例、行业动态）

### Step 1：安装 Skill

```bash
# 方式 1: 克隆到 WorkBuddy skills 目录
git clone https://github.com/huangjun124114/content-ops-automation.git \
  ~/.workbuddy/skills/content-ops-automation

# 方式 2: 直接下载
# 下载 ZIP 后解压到 ~/.workbuddy/skills/content-ops-automation/
```

### Step 2：初始化项目目录

```bash
python scripts/init_content_ops.py <项目根目录>
```

生成的目录结构：

```
<项目根目录>/
├── content-pipeline/
│   ├── pipelines/              ← 每条流水线一个目录
│   │   └── archive/            ← 已完成流水线归档
│   ├── config/
│   │   ├── 内容排期策略.md
│   │   └── 配置参数表.md
│   ├── registry.md             ← 流水线注册表（全局总览）
│   └── dashboard.html          ← 可视化仪表盘
├── brand-context/
│   ├── 产品介绍/
│   ├── 参考案例/
│   ├── 行业动态/
│   └── 风格指南/
└── skills/                     ← 专家 Skill 文件
    ├── policy-writer.md
    ├── industry-writer.md
    ├── product-writer.md
    ├── painpoint-writer.md
    └── polisher.md
```

### Step 3：配置品牌上下文

在 `brand-context/` 目录下放置以下资料：

1. **产品介绍**：产品功能、定位、目标客户
2. **参考案例**：历史发布的优质文章（5-10 篇）
3. **行业动态**：素材来源（可对接外部采集任务）
4. **风格指南**：写作风格规范（可从参考案例自动提炼）

### Step 4：启用调度器

在 WorkBuddy 中创建两个 Automation：

```yaml
# L0：每日写作计划（工作日 08:00）
name: L0-每日写作计划
scheduleType: recurring
rrule: "FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=8;BYMINUTE=0"
prompt: |
  执行今日写作计划：
  1. 读取内容排期策略，确定默认内容类型
  2. 执行动态排期检查（热点优先 > 素材质量 > 历史均衡）
  3. 扫描素材库，选择最佳题材
  4. 创建流水线实例，写入 registry.md
  5. 推送通知（含 5 分钟确认提示）

# L1：流水线调度器（每小时 1 次）
name: L1-流水线调度器
scheduleType: recurring
rrule: "FREQ=HOURLY;INTERVAL=1"
prompt: |
  扫描所有活跃流水线，按状态机规则推进：
  - 选题就绪 → 检查是否已确认（5分钟自动确认）
  - 选题确认 → 匹配专家，开始创作
  - 草稿完成 → 调用打磨师润色
  - 润色完成 → 推送审批通知
  - 审批通过 → 归档
  每次状态变更后更新 registry.md 和 dashboard.html
```

### Step 5：开始使用

明天早上 08:00，第一条流水线会自动创建。你也可以手动触发：

> "执行今日写作计划"

## 🎯 使用场景

### 场景 1：SaaS 产品内容运营

**挑战**：每周需要发布 5-7 篇内容（产品更新、行业洞察、客户案例），但只有 1 个运营人员。

**解决方案**：
- 配置 5 个专家角色（政策解读、行业观察、产品布道、痛点猎手、内容打磨）
- 每日自动创建流水线，工作日 08:00 自动启动
- 人工只需每日花 30 分钟审批 + 微调

**效果**：
- 内容产出从 2 篇/周 → 7 篇/周
- 人力投入从 20h/周 → 5h/周
- 内容质量持续提升（基于效果数据优化）

### 场景 2：多平台内容分发

**挑战**：需要在公众号、知乎、头条等多平台同步发布，但内容风格不一致。

**解决方案**：
- 在品牌上下文中配置统一风格指南
- 内容打磨师负责确保品牌一致性
- 不同平台可配置不同的内容模板

**效果**：
- 内容风格统一
- 多平台同步发布
- 品牌认知度提升

### 场景 3：热点快速响应

**挑战**：行业热点出现时，需要快速产出解读文章，但流程太长来不及。

**解决方案**：
- 手动触发临时流水线（不受每日限制）
- 状态机驱动，上一阶段完成立即触发下一阶段
- 政策解读专家优先匹配

**效果**：
- 热点响应时间从 24h → 2h
- 不再错过任何行业热点

## 🔧 技术细节

### 状态机定义（12 阶段）

```
新创建 (created)
  ↓ 选题完成
选题就绪 (topic_ready)
  ↓ 自动/手动确认
选题确认 (topic_confirmed)
  ↓ 匹配专家
创作中 (writing)
  ↓ 草稿完成
草稿完成 (draft_complete)
  ↓ 调用打磨师
润色中 (polishing)
  ↓ 润色完成
润色完成 (polish_complete)
  ↓ 推送审批
审批中 (reviewing)
  ↓ 审批通过
已完成 (completed)
  ↓ 30 天后
已归档 (archived)
```

### 专家匹配规则

```python
TYPE_EXPERT_MAP = {
    "政策解读": "policy-writer",
    "借势型": "policy-writer",
    "行业动态": "industry-writer",
    "资讯月报": "industry-writer",
    "产品功能": "product-writer",
    "体验升级": "product-writer",
    "痛点场景": "painpoint-writer",
    "客户故事": "painpoint-writer",
}

def match_expert(content_type: str) -> str:
    return TYPE_EXPERT_MAP.get(content_type, "industry-writer")
```

### 进化触发条件

| 触发条件 | 进化级别 | 执行动作 |
|---------|---------|---------|
| 每次流水线完成 | 记录 | 追加效果数据到 evolution-log |
| 每发布 5 篇 | 微进化 | 优化当前最有效的专家模板 |
| 每发布 10 篇 | 中进化 | 审视选题策略 + 排期规则 |
| 每发布 30 篇 | 大进化 | 全面审视架构、专家池、调度规则 |
