# 内容自动化运营框架 V4.2

## 一、概述

### 适用场景

本框架适用于以下场景：
- 需要每日产出多篇内容（公众号、知乎、头条等）
- 运营团队人力有限（1-2人），需 AI 承担 80%+ 工作量
- 需要多平台同步发布，内容风格统一
- 希望内容质量持续提升（基于效果数据优化）

### 核心价值

1. **人力节省 85%**：日常运营从 20h/周 降至 3-5h/周
2. **质量持续提升**：固定专家池 + 独立技能 + 进化闭环，越用越专业
3. **全流程可视**：dashboard.html + exec-log.md 台账，进度一目了然
4. **数据驱动优化**：发布→审批反馈→进化分析→优化技能→下一篇更好

### 前置条件

- WorkBuddy 桌面智能体（核心引擎）
- IMA 知识库或本地文件系统（存储素材和稿件）
- 企微 Bot Webhook（通知渠道）
- 品牌上下文资料（产品介绍、参考案例、行业动态）

## 二、V4.2 架构（2026-08-12 整改）

### 核心认知

**每次定时运行都是独立新会话（无上次记忆），用户回复才会延续会话。不依赖会话记忆，只依赖文件系统状态。**

### 设计命题

平台限制（每次定时调度=无记忆新会话）不阻断业务连续性，只要求状态外部化；各阶段是"给定文件+协议即自足"的纯函数步骤。

### 单一集成调度器

一个 Automation 承担全部调度职责（模式A选题 + 模式B推进 + 模式C用户交互）：

```
┌──────────────────────────────────────────────────────────────┐
│  集成调度器（单一 Automation，模式A/B/C 自动切换）              │
│                                                              │
│  模式A（工作日08-12点）：推荐3选题 → 企微通知 → 等用户选        │
│  模式B（定时触发）：扫描 pipelines/ → 推进一个阶段 → 结束      │
│  模式C（用户回复）：选题创建 / 审批执行 / 普通问答              │
├──────────────────────────────────────────────────────────────┤
│  文件系统（单一数据源）                                        │
│                                                              │
│  status.md = 每条流水线的唯一事实来源                           │
│  exec-log.md = 台账（只记有动作的行）                           │
│  registry.md + dashboard.html = 全局视图（成对同步）            │
├──────────────────────────────────────────────────────────────┤
│  技能层（8个独立 Skill 文件）                                   │
│                                                              │
│  4个创作专家 + 3个辅助技能 + 1个分析技能                       │
│  每个技能独立可触发、独立可进化                                 │
└──────────────────────────────────────────────────────────────┘
```

### 与旧架构对比

| 维度 | V3（旧） | V4.2（现行） |
|------|---------|-------------|
| 调度器 | 2-3个 Automation（L0/L1/L2） | 单一集成调度器 |
| 流水线管理 | TaskCreate/TaskUpdate 任务项 | 文件状态机（status.md） |
| 选题方式 | 自动选题（5分钟超时确认） | 推荐3选题→用户人工选择 |
| 部署方式 | CloudStudio 唯一 | COS 优先、CloudStudio 兜底 |
| 会话依赖 | 假设会话有记忆 | 每次新会话、状态外部化 |
| 防重叠 | 无 | 执行锁（_locked_until） |

## 三、铁律（V4.2 核心约束）

1. **状态外部化**：status.md 是唯一事实来源，不依赖会话记忆
2. **执行锁**：推进前设 `_locked_until=当前+50min`，完成后清空；锁未过期则跳过
3. **提交顺序**：先写工件 → 追加 exec-log → 最后改 status.md（崩溃可重做）
4. **台账必记**：每次有动作的运行在 exec-log.md 追加一行
5. **单阶段原则**：模式B 每次只推进一个阶段，完成后立即结束
6. **绝对禁止**：TaskCreate / TaskUpdate / automation_update
7. **部署幂等**：preview.html 已存在且比 review.md 新、URL 非空 → 复用
8. **成对同步**：registry.md 和 dashboard.html 必须同时更新
9. **审批真实来源**：只认用户真实回复或 approval_action 字段（该字段也只由用户写入）
10. **定时运行不创建流水线**：只有用户真实选题回复（模式C）才能触发创建
11. **等待审批不擅自动作**：无用户指令时只记台账后结束
12. **通知频控**：每次运行最多1条企微通知（仅部署→等待审批、归档两个节点发）

## 四、独立技能清单

所有专家技能为独立的 `.md` 文件，位于 `.workbuddy/skills/` 目录下：

### 创作专家（4个）

| 技能文件 | 角色 | 负责内容类型 | 调用者 |
|---------|------|------------|--------|
| `yzy-policy-writer.md` | 📋 政策解读者 | 政策解读、借势型 | 调度器（政策解读类→AI创作阶段） |
| `yzy-industry-writer.md` | 📰 行业观察家 | 行业动态、资讯月报 | 调度器（行业观察/月报类→AI创作阶段） |
| `yzy-product-writer.md` | 🚀 产品布道师 | 产品功能、体验升级 | 调度器（产品功能类→AI创作阶段） |
| `yzy-painpoint-writer.md` | 💡 痛点猎手 | 痛点场景、客户故事 | 调度器（痛点场景类→AI创作阶段） |

### 辅助技能（3个）

| 技能文件 | 角色 | 职责 | 调用者 |
|---------|------|------|--------|
| `yzy-polisher.md` | 🔍 内容打磨师 | 去AI味+事实核查+品牌一致性+竞品红线 | 调度器（所有类型→润色阶段） |
| `yzy-deploy-assistant.md` | 🚀 部署助手 | COS部署（优先）/ CloudStudio（兜底） | 调度器（部署预览阶段） |
| `yzy-approval-assistant.md` | 📋 审批助手 | 生成通知+推送企微+记录feedback.md | 调度器（审批阶段） |

### 分析技能（1个）

| 技能文件 | 角色 | 职责 | 调用者 |
|---------|------|------|--------|
| `yzy-evolution-analyst.md` | 🧬 进化分析师 | 分析反馈→识别模式→更新技能→记录日志 | 每周五或手动触发 |

### 技能进化机制

```
用户审批退回 → feedback.md 结构化记录 → L2 每周分析
    → 识别退回模式（如"竞品引用"连续出现2次）
    → 自动更新对应技能 SKILL.md 的写作规范
    → 记录 evolution-log.md（版本号+变更+数据依据）
    → 下一篇验证：通过→进化成功 ✅ / 再退回→继续迭代 🔄
```

每个技能维护独立的 `yzy-{expert}-evolution-log.md` 进化日志。

## 五、流水线管理

### 状态机（8阶段）

```
选题确认 → AI创作 → 内容润色 → 部署预览 → 等待审批 → 已完成（归档）
                                                      ↓ 退回
                                               AI重写 → 润色 → 部署 → 审批
```

### status.md 模板（唯一事实来源）

```markdown
# 流水线状态
- 流水线ID: PL-YYYYMMDD-NNN
- 当前阶段: {阶段名}
- 创建时间: YYYY-MM-DD HH:MM
- _last_advance: YYYY-MM-DD HH:MM
- _locked_until: 
- cloudstudio_url: （存放COS预览URL，字段名沿用）
- approval_action: （仅用户消息写入）
```

### 流水线目录结构

```
pipelines/PL-YYYYMMDD-NNN/
├── topic.md           # 选题文档（模式C 创建）
├── status.md          # 状态跟踪（调度器更新）
├── exec-log.md        # 台账（每次有动作的运行追加一行）
├── draft.md           # AI 初稿
├── review.md          # 润色稿
├── feedback.md        # 结构化审批意见（进化数据源）
├── preview.html       # 预览页（COS部署用）
└── final.md           # 归档终稿
```

### exec-log.md 台账格式

每次有动作的运行追加一行：

```
| 时间 | 模式 | 迁移 | 工件 | 结果 |
```

- 时间必须来自 `date` 命令的真实系统时间
- 只录有动作的行（推进阶段/推荐选题/创建流水线/审批/异常）
- 不录：夜间静默/无操作/用户未回复/周末跳过

### 全局视图文件

- **registry.md**：活跃流水线表 + 已完成流水线表（含统计）
- **dashboard.html**：可视化看板（header 最后更新时间用 `date` 真实时间）
- 铁律8：两者必须成对同步更新

### feedback.md 格式（进化数据源）

```markdown
# 审批反馈
- 流水线ID: PL-YYYYMMDD-NNN
- 内容类型: {type}
- 版本: V1
- 审批结果: 退回 | 修改后通过 | 通过
- 修改意见: [逐字记录用户意见原文]
- 问题分类: [竞品引用 | 品牌调性 | 数据准确性 | 结构问题 | 无]
- 涉及技能: [yzy-xxx-writer]
- 影响进化: 是/否
- 进化建议: [具体建议]
```

## 六、部署架构（V4.2）

### COS 部署（首选）

- **桶**：workbuddy-1301205400 / ap-guangzhou
- **对象路径**：`yzy-preview/<pipeline_id>/index.html`
- **部署脚本**：`config/cos-deploy.py`（SecretId 内置，SecretKey 在 `~/.workbuddy/.env`）
- **命令**：`python config/cos-deploy.py <html路径> <pipeline_id>`
- **URL 格式**：`https://workbuddy-1301205400.cos.ap-guangzhou.myqcloud.com/yzy-preview/<pipeline_id>/index.html`

### CloudStudio（兜底）

- 仅在 COS 部署失败时启用
- 已知缺陷：沙箱复用导致不同流水线 URL 相同、内容互相覆盖

## 七、企微通知

### 通知脚本

通过 `config/wecom-notify.py` 发送，禁止裸 curl：

```
python config/wecom-notify.py "消息内容"
```

### 通知模板（严格遵守）

| 通知类型 | 触发场景 | 字数限制 |
|---------|---------|---------|
| 选题推荐 | 模式A | 400字 |
| 创建任务 | 模式C选题 | 200字 |
| 审批通知 | 部署→等待审批 | 500字 |
| 归档通知 | 已完成归档 | 100字 |

## 八、核心原则（最高优先级）

### ⚠️ 内容生产核心原则（用户确认）

**所有内容的首要目标：通过资讯实现客户关注，核心目的是传递品牌方价值，实现客户拓展拿单。**

**竞品案例使用红线**：
- ❌ **禁止正面引用竞品案例**来佐证品牌方的能力
- ✅ 竞品动态只用于**描绘行业背景/痛点**
- ✅ 价值传递必须**用自己的客户数据、自己的功能、自己的案例**来证明
- ✅ 提及竞品后必须**立即转回品牌方视角**

**每篇文章的核心判断标准**：
1. 读者看完是否记住了品牌方？（而非记住了竞品）
2. 读者看完是否产生了"品牌方能帮我解决这个问题"的认知？
3. 读者看完是否有行动意愿（咨询/试用/关注）？

### 进化边界

| 范围 | 权限 |
|------|------|
| **可自动更新** | 专家模板写作规则、合规检查清单、配图建议 |
| **需用户确认** | 新增/删除专家角色、修改调度频率、修改核心原则 |
| **不可更新** | 竞品红线、品牌定位、状态机定义、铁律 |

## 九、配置参考

### 排期策略（默认）

| 星期 | 内容类型 | 匹配专家 |
|------|---------|---------|
| 周一 | 政策解读 | 📋 政策解读者 |
| 周二 | 行业观察 | 📰 行业观察家 |
| 周三 | 产品功能 | 🚀 产品布道师 |
| 周四 | 痛点场景 | 💡 痛点猎手 |
| 周五 | 行业月报 | 📰 行业观察家 |
| 周六/日 | 休息 | - |

排期为默认建议，调度器会根据热点/素材质量/历史分布动态调整并推荐选题。

### 调度时间

- **rrule**：`FREQ=HOURLY;INTERVAL=1;BYDAY=MO,TU,WE,TH,FR`（工作日整点触发）
- **夜间静默**：22:00-07:59 无用户回复则快速退出
- **模式A窗口**：工作日 08:00-11:59（含补触发至12:00）

### 归档策略

- 已完成流水线保留 30 天（status.md 标记已完成）
- 30 天后目录移动到 `pipelines/archive/`
