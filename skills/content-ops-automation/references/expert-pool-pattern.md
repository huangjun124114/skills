# 专家池设计模式

> 版本：1.0 | 最后更新：2026-07-31

## 设计理念

固定专家池是本框架的核心创新之一。通过为每种内容类型配置专属专家，并为其创建独立的 Skill 文件，实现：

1. **专业化**：每个专家专注于特定类型，写作质量更高
2. **可迭代**：Skill 文件记录经验教训，越用越好
3. **可追溯**：每篇文章可追溯到具体专家，便于复盘
4. **可扩展**：新增内容类型只需新建专家 Skill

## 专家角色定义

| 专家角色 | Skill 文件 | 负责内容类型 | 核心能力 |
|---------|-----------|-------------|---------|
| 📋 政策解读者 | `policy-writer.md` | 政策解读、法规分析 | 政策拆解→影响分析→建议 |
| 📰 行业观察家 | `industry-writer.md` | 行业动态、市场趋势 | 数据整合→趋势判断→洞察 |
| 🚀 产品布道师 | `product-writer.md` | 产品功能、体验升级 | 功能翻译→场景演示→价值传递 |
| 💡 痛点猎手 | `painpoint-writer.md` | 场景痛点、客户故事 | 故事构建→共情触发→方案植入 |
| 🔍 内容打磨师 | `polisher.md` | 所有类型的润色+合规 | 去 AI 味→事实核查→品牌一致性 |

## 专家匹配规则

```python
# 内容类型 → 专家映射
TYPE_EXPERT_MAP = {
    "政策解读": "policy-writer",
    "借势型": "policy-writer",      # 借势政策归政策解读者
    "行业动态": "industry-writer",
    "资讯月报": "industry-writer",
    "产品功能": "product-writer",
    "体验升级": "product-writer",
    "痛点场景": "painpoint-writer",
    "客户故事": "painpoint-writer",
    "观点型": "industry-writer",    # 观点类归行业观察家
}

def match_expert(content_type: str) -> str:
    """根据内容类型匹配对应专家"""
    return TYPE_EXPERT_MAP.get(content_type, "industry-writer")
```

## 专家迭代机制

### 迭代触发条件

| 触发条件 | 动作 |
|---------|------|
| 文章阅读量 < 500 | 分析原因，更新"避坑指南" |
| 文章阅读量 > 2000 | 提炼成功经验，更新"高转化模板" |
| 用户反馈修改意见 | 记录修改点，更新"合规检查清单" |
| 每完成 5 篇文章 | 全面复盘，更新 Skill 版本 |

### 迭代记录格式

```markdown
### 迭代记录

#### v1.2 (2026-08-15)
- 更新内容：优化"产品植入"段落过渡
- 触发原因：用户反馈"植入太生硬"
- 修改点：将"悠租云提供 XX 功能"改为"运营方可以..."

#### v1.1 (2026-08-05)
- 更新内容：增加"数据引用必须标注出处"规则
- 触发原因：首篇文章被质疑数据来源
- 修改点：在合规检查清单中增加此项

#### v1.0 (2026-07-31)
- 初始版本
```

## 新增专家角色流程

当需要覆盖新的内容类型时，按以下流程新增专家：

1. **定义角色**：确定专精领域、写作风格、目标受众
2. **创建 Skill 文件**：按上述规范创建 `<expert-name>.md`
3. **配置匹配规则**：在 `TYPE_EXPERT_MAP` 中新增映射
4. **测试创作**：用新专家创作 1-2 篇文章，验证质量
5. **迭代优化**：根据效果数据和用户反馈持续优化

**注意**：新增专家角色需要用户确认（属于"需用户确认"的进化边界）。

## 打磨师（Polisher）特殊说明

打磨师是所有专家的后置环节，负责：

1. **去 AI 味**：消除 AI 生成痕迹（如"赋能""颠覆"等词）
2. **事实核查**：核对数据、政策引用是否准确
3. **品牌一致性**：确保符合品牌风格指南
4. **合规检查**：检查敏感词、竞品提及等

打磨师的 Skill 文件应包含所有专家类型的通用规范。
