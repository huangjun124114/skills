# 流水线状态机规范

> 版本：1.1 | 最后更新：2026-07-31

## 状态机定义

每条流水线经历 13 个阶段：

```
┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
│ 新创建  │──▶│选题就绪│──▶│选题确认│──▶│创作中  │
└────────┘   └────────┘   └────────┘   └────────┘
                                              │
                                              ▼
┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
│ 已归档  │◀──│已完成  │◀──│审批中  │◀──│部署预览│
└────────┘   └────────┘   └────────┘   └────────┘
                ↑                               │
                │                               ▼
                │                          ┌────────┐
                └──────────────────────────│润色完成│◀──│润色中  │
                                           └────────┘   └────────┘
```

## 阶段说明

| 阶段 | 执行者 | 说明 | 产出物 |
|------|--------|------|--------|
| 新创建 | L0 | 流水线刚创建 | — |
| 选题就绪 | L0 | 选题推荐完成，等待确认 | topic.md |
| 选题确认 | 人工/自动 | 用户确认或 5 分钟自动通过 | — |
| 创作中 | L2 专家 | AI 正在创作 | draft.md |
| 草稿完成 | — | AI 草稿已生成 | draft.md |
| 润色中 | L2 打磨师 | 正在润色 | review.md |
| 润色完成 | — | 终稿已生成 | review.md |
| **部署预览** | **L1 调度器** | **将终稿转为 HTML 预览页并部署到静态托管，推送企微通知（含预览链接）** | **preview.html + preview-url** |
| 审批中 | 人工 | 等待人工审批（用户通过预览链接阅读后审批） | — |
| 已完成 | — | 审批通过，归档完成 | final.md |
| 已归档 | — | 完成 30 天后自动归档 | — |

## 部署预览阶段详细说明

### 触发条件

「润色完成」阶段结束后，L1 调度器自动进入「部署预览」阶段。

### 执行步骤

1. **生成 HTML 预览页**
   - 读取 review.md（润色后终稿）
   - 使用品牌风格模板生成 HTML 预览页（preview.html）
   - 包含：标题、正文、配图建议占位、流水线信息、品牌标识

2. **部署到静态托管**
   - 优先使用 CloudStudio Deploy
   - 备选：EdgeOne Pages / 本地 HTTP Server
   - 获取可访问的 URL（preview-url）

3. **推送审批通知**
   - 通过企微 Bot / 邮件 / 钉钉推送通知
   - 通知内容包含：流水线 ID、文章标题、字数、专家信息、**预览链接**
   - 用户点击链接即可在线阅读并审批

4. **状态变更**
   - 部署成功 → 状态变为「审批中」，记录 preview-url
   - 部署失败 → 回退到「润色完成」，记录错误日志

### 产出物

- `preview.html`：HTML 预览页（保存在流水线目录）
- `preview-url`：可访问的 URL（记录在 status.md）

### 通知模板

```
📝 终稿已就绪，请审批

流水线：{pipeline_id}
标题：{article_title}
字数：{word_count} 字
创作专家：{creator_expert}
润色专家：{polisher_expert}

📖 预览链接：{preview_url}

请回复"通过"或修改意见
```

## 归档策略

### 归档规则

1. **保留期限**：已完成流水线保留 30 天（可配置）
2. **归档触发**：L1 调度器每次运行时检查已完成流水线
3. **归档操作**：
   - 将流水线目录从 `pipelines/` 移动到 `pipelines/archive/`
   - 更新 `registry.md` 状态为"已归档"
   - 从 L1 调度器的活跃列表中移除
4. **归档后访问**：
   - 归档流水线仍可通过 `registry.md` 查询
   - 文件保留在 `pipelines/archive/` 目录
   - 可随时手动恢复（移回 `pipelines/`）

### 归档配置

```yaml
archive:
  retention_days: 30          # 保留天数
  auto_archive: true          # 是否自动归档
  archive_directory: "pipelines/archive/"
  preserve_files: true        # 是否保留所有文件
```
