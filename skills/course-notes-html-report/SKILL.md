# 课程要点还原报告：多源材料 → 可二次输出的 HTML

用于「我刚参加了一场培训，空间里有全部材料，帮我输出完整课程要点」这类需求。

**核心价值不在样式，而在三件事**：**可核查的事实分层 + 可复用的资产清单 + 一眼看到全局的知识地图**。
多数人把课程整理做成「要点摘抄」——那没有二次输出的价值。

> **本技能专注「内容还原的方法论 + 样式/交互/照片的硬规范」。**
> HTML 构建与渲染验证的通用工程细节（分片拼接、内联 Chart.js、探针写法）
> 另见配套技能 **`html-data-report`**，本技能不重复。
>
> 技能包结构：`references/`（七份规范，按需读）+ `scripts/`（19 个可跑脚本）+ `assets/`（样式骨架与侧栏模板）。

---

## 0. 先对齐，再动手（**唯一硬门禁，不要跳**）

这类任务信息量大、返工代价高。**必须先读完材料 → 出方案 → 等确认**。

用 AskUserQuestion 一次问清四件事（给推荐项，不要开放式提问）：

| 必问项 | 典型选项 | 不问的后果 |
|---|---|---|
| **覆盖范围** | 全部场次 / 只做有录音的场次 | 白写一半，或漏写用户最想要的 |
| **详略程度** | 速览版 / 详尽版（二次输出素材库） | 写得过简被退，或过度冗长 |
| **「我的总结」视角** | 第一人称（结合用户身份/公司）/ 中性 / 不写 | 总结写成正确的废话 |
| **课件照片处理** | **双轨制**（照片 > 30 张）/ 只矢量重建（< 10 张）/ 不处理 | 选错要返工重做全部插图 |

**范围判定要先做材料盘点**：空间里常有「课表预告了但材料没到」的场次。
**没有录音/纪要/课件 = 不做推测性还原**，在附录里明确写出边界与原因。

```

                                                                        │
     ┌──────────────────────────────────────────────────────────────────┘
     ▼
S4 骨架+样式系统 ──▶ S5 分节撰写 ──▶ S6 构建 ──▶ S7 五层验证 ──▶ S8 交付/派生/发布 ──▶ S9 沉淀
```

| 阶段 | 动作 | 产出 | 通过闸门 |
|---|---|---|---|
| **S0** | 清点材料（四类源 + 张数/页数/字数） | 材料清单 | 四类源都有去向，缺失项已记录 |

| **S9** | 写日志 + 更新技能 | 记忆 + SKILL.md | 新坑与参数已落盘 |

## 2. 材料盘点：四类源与阅读顺序

| 源类型 | 读法 | 主要用途 | 注意事项 |
|---|---|---|---|
| **课堂纪要** | 通读全文 | 骨架：章节顺序、模块边界 | 最可靠的结构来源 |
| **讲师手册** | 通读，Prompt 原文抄录 | 官方结构 + Prompt 全文 | 手册里的 Prompt 是**最高价值可复用资产，必须原文收录** |
| **录音转写** | `grep` 关键词定位后精读**上下各 20 行** | 老师原话、比喻、临场补的例子 | **同音误记重灾区** |
| **课件照片** | 索引拼图 → 单张精读 | 框架图、数据、页内文案 | 与转写互补（看的是 PPT 上写了什么） |
| **外部研报** | 只取被课堂引用到的部分 | 模型出处 | 不要整份塞进去 |

**阅读顺序（不要颠倒）**：纪要（骨架）→ 手册（结构与 Prompt）→ 转写（原话）
→ 课件照片（视觉确认）→ 外部研报（补出处）。

> 为什么不顺序通读转写：一场可达 10 万字。先拿纪要建骨架，再按概念 grep 精读，
> **原话的价值往往在上下文里**，单独一行会被误读。

## 3. 三条必须记住的判定标准 ⭐

### ① 照片怎么处理

| 照片数 | 方案 |
|---|---|
| **> 30 张** | **目录式 + 双轨制**（`index.html` + `images/`；照片嵌入 **且** 核心框架矢量重建） |
| < 10 张 | 单文件 + 纯矢量重建即可 |

> **两轨解决的是不同问题，照片密集场次必须都要**：照片是现场证据但不可检索，
> 重建图可检索但可能抄错。单文件 base64 会把 20 MB 图塞进正文，编辑器打不开。

### ② 「我的总结」合不合格

三段里**至少一段是判断或行动**（① 翻译 ② 判断 ③ 落地）。
三段全是「老师说得对」→ 不合格，必须重写。质量闸门：`节数 == .mine 数`。

### ③ 能不能做推测性还原

**只有讲义、没有录音/纪要/课件照片的场次 → 不做。**
写进附录「覆盖边界说明」与交付说明。**不要用讲义去「写」一堂没听过的课。**

## 4. 内容还原（要点）

**四档忠实度标注**——这是整份报告的生命线，读者必须能一眼分清
「哪些能直接引用、哪些要核对、哪些是我的判断」：

| 档位 | 组件 | 视觉 | 纪律 |
|---|---|---|---|
| ① 老师原话 | `.quote` | 金框 | **逐字还原，不改写、不润色** |
| ② 课堂数据 | `.quote.d` | 青框 | 数字原样，**未做独立复算**则须声明 |
| ③ 复算校验 | 数据表 + `.note` | 中性 | **拿不到同一数据集就不做**，别硬造 |
| ④ 我的总结 | `.mine` 🦞 | 绿框 | 必须与前三档**视觉可区分** |

**最致命的错误**：把「我的推断」和「老师原话」混在同一个样式里 → 可信度归零。
**页脚必须放四档图例**；附录再放一次「未做复算 + 原因」。

其余规则（转写误记三原则与误记词典、课件内部矛盾**原样保留不统一**、遮挡补齐必须留痕、
章节架构模板、知识地图与一页纸速览、附录必备五项）→ 见
**`references/01-content-restoration.md`**。

## 5. 课件照片处理（要点）

**索引拼图法**：110 张照片逐张 Read = 110 次调用，太贵。
先用 `make_sheets.py` 压成 12 张 3×3 拼图（每格带 `pNNN + 时间戳` 黄标签），
**一次 Read 看 9 张**，12 次看完全部 → 建立映射 → 再对核心框架图（约 20 张）逐张精读原图。

**照片编号顺序 = 课程顺序**（文件名时间戳即讲课顺序），这是「照片自动归位」的依据。

**压缩双管线**（实测均值）：

| 用途 | 宽度 | 质量 | 均值 |
|---|---|---|---|
| 大图（灯箱） | 1400px | 78 | 129 KB |
| 缩略图（网格） | 560px | 72 | 28.3 KB |

体积预算：132 张 ≈ **20.3 MB**（上限约 30 MB）。

**三处呈现形态**：① 正文配图（每节挑最关键的 1—4 张）② 章末分组相册 ③ 附录总览相册
（②③ 由 `image_map.json` **自动生成**，绝不手写索引 —— 否则必然与素材脱节）。

完整参数（拼图参数表、去重规则与剔除率经验值、编号与手册去重、`image_map.json` 结构、
相册自动生成算法与占位符机制、`kfig` 重建要求、懒加载与只读纪律）→ 见
**`references/02-photo-pipeline.md`**。

## 6. 样式与交互规范（要点）

**深色主题固定**（交付物是独立分发的文档，不跟随宿主 IDE 主题）。
设计令牌写在 `head.html` 的 `:root`，**唯一真源**，改样式只改这一处，不许用行内样式。

**色彩语义不得随意换色**：

| 颜色 | 语义 |
|---|---|
| 金 | 老师原话 / **下半场** / 品牌强调 |
| 蓝 | **上半场** / 信息提示 |
| 青 | 课堂数据 |
| 绿 | 我的总结 |
| 紫 | 可复用资产 / 标签 |
| 红 | 风险 / 卡点 |

> **上下半场双色体系是全篇最重要的视觉锚点**（`.am` / `.pm` 贯穿章节头、步骤序号、
> 表头、导航项、知识地图两列），让读者在任意位置都知道「我在上半场还是下半场」。

**八项交互行为契约**：Prompt 复制 · 照片灯箱 · 折叠相册懒加载 · 侧栏滚动高亮 ·
激活项自动入视野 · 阅读进度条 · 点击跳转锁定 · 窄屏抽屉。

**两条最容易被漏掉的实现要求**：

1. **复制按钮必须有 `file://` 降级**（`navigator.clipboard` 在非安全上下文常被拒）——
   没有降级路径 = 复制功能在「离线双击打开」这个主场景里全废。
2. **滚动监听必须 `rAF` + `setTimeout(done, 60)` 双保险**，rAF 在后台标签页/无头环境会被节流。

完整参数（23 个令牌、排版尺度表、20 组件清单、断点 1100/980/760、窄屏表格放行规则、
打印还原、6 条禁用项、8 项契约细则、复制状态机、灯箱契约、scroll spy 探针公式、
抽屉契约、可访问性、性能预算）→ 见
**`references/03-style-spec.md`** 与 **`references/04-interaction-spec.md`**。

## 7. 工程实现：分片构建（长报告必须这么做）

7 万字报告写在单文件里，任何一次编辑都要重读全文，成本爆炸且容易截断。

```
中间产物/<任务名>/
  head.html        # <title> + 全部 CSS（从 assets/head.html 起手）
  p1.html          # wrap 开始 + Hero + TOC + 00 速览 + 01 全景
  p2..pN.html      # 每片 2 节正文
  pN+1.html        # 工具箱 + 附录 + footer + </div> 收尾
  image_map.json   # 照片总表（prep_images.py 生成）
```

**硬要求**：

1. `head.html` **只放** `<title>` + `<style>`（不含 `<head>` 标签，由构建脚本套壳）；
2. 分片开头**不写** `<div class="wrap">`，只在 `p1` 开、末片关；
3. 分片顺序靠**文件名数字**排序（用 `int()`，否则 `p10` 会排到 `p9` 前面）；
4. 改样式只改 `head.html`，**不要用行内样式**；
5. 每片写完必须闭合自己的块级标签（`</section>`）。

`build_report.py` 做七件事：拼接 → 套壳 → 注入灯箱 DOM → 替换相册占位符 → 条件内联 Chart.js
→ 追加交互脚本 → **标签配平自检 + 内容统计**。

> 构建结束打印的那套统计数字（章节/原话/数据/总结/资产/Prompt/复制按钮/照片/相框/表格）
> 后面验证阶段要复用，**必须同一套口径**。

派生版（Markdown 归档、左侧导航版）的做法与坑 → 见 **`references/05-build-and-derive.md`**。

## 8. 五层验证（全部可复跑，不许只说「已检查」）

| 层 | 查什么 | 判定 |
|---|---|---|
| **L1 结构** | section id 无重复；站内链接都有落地章节；目录顺序 == 章节顺序 | 全通过 |
| **L2 资源** | 正文引用图片全部存在；大图都有缩略图入口；存在懒加载标记 | 零缺失 |
| **L3 一致** | Prompt 块数 == 复制按钮数；每节都有 `.mine` + `.asset` | 完全相等 |
| **L4 渲染** | 无头 Chrome 宽/窄截图成功；整页 PDF 生成成功 | 图 > 20 KB |
| **L5 窄屏真视口** | iframe 定宽 360/390/480px：无横向溢出，**容器外**越界元素 0 | 全绿 |

**内容层另有三层人核**：四档是否都在 · 误记是否就近标注且正文未改 · 附录是否写明覆盖边界。

**「正文零改动」的硬证据**：新旧两版从 `<div class="wrap">` 起逐字节比对，
并断言「新版 style 块以原版 style 块为**前缀**」→ 证明是**追加而非改写**；
再加 9 项组件计数相等、原版文件字节数与 mtime 未变。

## 9. 交付

**四件套（缺一不可）**：

```
输出/<报告名>_<MMDD>/
├── index.html                    ← 主报告，双击即开
├── images/                       ← 大图 + t/ 缩略图（必须与 index.html 同级）
```

## 10. 常见坑（Top 6，完整 30 余条见 `references/07-pitfalls.md`）

1. **无头 Chrome「滚动后截图」会截到空白页**（纯白图，不是深色底）→
   **把目标 `<section>` 抽出来单独成页再截**；验证 `position:fixed` 元素时干脆不滚动，
   脚本直接置高亮态再截首屏。
2. **无头 Chrome 最小窗口宽约 485px** → 测 390px 必须用 **iframe 定宽**，不能靠 `--window-size`。
3. **`--virtual-time-budget` 下 `scroll` 事件不自动派发、rAF 不回调** →
   探针手动 `dispatchEvent(new Event('scroll'))`；产品侧 `rAF` + `setTimeout` 双保险。
4. **文档级「零溢出」≠ 内容看得全**：`overflow-x:auto` 容器把内容憋在内部滚动时探针报零溢出，
   末格却被切。**必须另跑「容器内滚动」检测，并靠截图目视确认**；
   反过来，查越界元素时**必须跳过滚动容器内的元素**（否则假警报）。
5. **`--dump-dom` 换行是 `\r\n`** → 结果正则用 `([\s\S]*?)`，别写 `\n`；
   取不到结果时先打印 stdout 长度与标记命中情况（stderr 是空的，看不出问题）。
6. **Markdown 转换：`block()` 返回值类型不统一会让整篇按单字拆开，而且不报错** →
   统一为 list；块标签用 `plain()` 取（`inline()` 会跳过 `.lb`）。

**本机环境**：bash 每条命令前导出 PATH；`crashpad` 日志无害用 `grep -av` 过滤；
curl 要加 `--ssl-no-revoke` 且不要 `-o /tmp/...`；判 DNS 用 DoH 不用 `nslookup`。
