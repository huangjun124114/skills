# 内容还原与总结规范

> 这是报告的**价值本体**。样式再好，内容错位就是废纸。
> 多数人把课程整理做成「要点摘抄」；真正有用的是
> **可核查的事实分层 + 可复用的资产清单 + 一眼看到全局的知识地图**。

---

## 1. 四类源的分工与阅读顺序

| 源类型 | 读法 | 主要用途 | 注意事项 |
|---|---|---|---|
| **课堂纪要** | 通读全文 | 骨架：章节顺序、模块边界 | 最可靠的结构来源 |
| **讲师手册 / 操作手册** | 通读，Prompt 原文抄录 | 官方结构 + Prompt 全文 | 手册里的 Prompt 是**最高价值可复用资产，必须原文收录** |
| **录音转写** | `grep` 关键词定位后精读 | 老师原话、比喻、临场补的例子 | **同音误记重灾区**（见 §5） |
| **课件照片** | 索引拼图 → 单张精读 | 框架图、数据、页内文案 | 看的是「PPT 上写了什么」，与转写互补 |
| **外部研报** | 只取被课堂引用到的部分 | 模型出处 | 不要整份塞进去 |

**阅读顺序（不要颠倒）**：纪要（骨架）→ 手册（结构与 Prompt）→ 转写（原话，按概念 grep 后精读）
→ 课件照片（视觉确认）→ 外部研报（补出处）。

**为什么先读纪要**：纪要长度通常只有转写的一半，但结构更清晰。
先拿它建好章节骨架，再回转写里按概念 grep 填血肉，比从头通读转写高效一个数量级。

**转写精读的做法**：不要顺序通读。用关键词（概念名、老师口头禅、数字）grep 出候选行，
再精读**上下各 20 行**——原话的价值往往在上下文里，单独一行会被误读。

## 2. 忠实度四档标注（最高优先级）

**这是整份报告的生命线**：读者必须能一眼分清「哪些能直接引用、哪些要核对、哪些是我的判断」。

| 档位 | 组件 | 视觉 | 内容要求 | 写作口径 |
|---|---|---|---|---|
| ① **老师原话** | `<div class="quote">` | 金框 + 左侧 3px 金边 | 逐字还原，**不改写、不润色** | 加引号；口癖可保留（`那个`/`就是说`） |
| ② **课堂数据** | `<div class="quote d">` | 青框 + 青边 | 数字原样，**未做独立复算** | 标注口径来源 |
| ③ **复算校验** | 数据表 + `.note` 说明 | 中性 | 只有拿到同一数据集才做 | **拿不到就不做**，并在页脚声明 |
| ④ **我的总结** | `<div class="mine">` 🦞 | 绿框 + 🦞 图标 | 用户视角的判断、迁移、行动 | 必须与前三档**视觉可区分** |

**第四档的补充组件**：

| 组件 | 用途 | 写法 |
|---|---|---|
| `.asset`（紫虚框） | 可复用资产 | 动作动词开头，一行一条，可直接抄进待办 |
| `.hl`（红/绿/蓝） | 卡点 / 风险 / 提示 | 红=坑与风险，绿=正面确认，蓝=中性提示 |
| `.kfig`（「重建」标签） | 矢量重建的框架图 | 字段必须与课件原文一致 |

### 反例（最致命的错误）

> 把「我的推断」和「老师原话」混在同一个样式里 —— 读者无法区分哪些可以对外引用、
> 哪些需要回看录像核对。**一旦混淆，整份报告的可信度归零。**

**页脚必须放四档图例**，把四档和上下半场色标一次性讲清；附录再放一次「未做复算 + 原因」。

### 复算校验做与不做的判定

- **做复算**的前提是「课堂结论建立在某份可获取的数据集上」（如公开的 Superstore 数据集）。
  用同一份数据独立跑一遍，把「折扣 xxx% 转亏」这类口述结论落到精确数字上，
  报告的价值就从「记录」升级为「证据」。**但必须标注来源差异，否则就是伪造。**
- **不做复算**的情形：整场课的数字都来自讲者自家服务口径（客户曝光量、销量、利润率），
  外部根本无法复算。**这时候不要硬造复算**。正确做法是：
  ① 页脚与附录显式声明「**未做独立复算 + 原因**」；
  ② 所有数字一律按「课堂数据」原样标注（**不统一、不修正**）；
  ③ 在附录做一张**关键数字索引表**（数字 / 含义 / 出自哪一节的哪张课件），供日后核查与引用时标注来源。

## 3. 「我的总结」写法公式 ⭐

每小节**必须有**一段 `.mine`。它不是复述，而是**把老师的结论翻译成自己组织可执行的东西**。三段式：

| 段 | 任务 | 句式模板 | 反例（不要这样写） |
|---|---|---|---|
| ① **翻译** | 点出老师话里的隐含前提或可迁移的判断标准 | 「老师这套方法真正的门槛不在 X，而在 Y。」 | 「老师讲了 X，很重要。」 |
| ② **判断** | 给出自己的口径/排序/取舍 | 「我的口径是：先 …，再 …，最后才 …。」 | 「这个说法有道理。」 |
| ③ **落地** | 落到自己组织的一次具体动作 | 「回到我们这边，第一件事是 …。」 | 「值得学习。」 |

**好例（实测）**：

- → 「老师这句『业绩是人干出来的』真正的落点不是否定技术，而是**给技术划边界**：技术负责放大，人负责决定放什么。」
- → 「老师讲 GTM 的完整路径，我的判断是：**先别急着做产品页，先去做平台上的用户信号采集**。」
- → 「战略双轨制的真正用法不是选边，而是**把大 B 当保命、把小 B 当造血**，两条线同时跑。」

**质量闸门**：`节数 == .mine 数`，且**每段都含「判断」或「行动」**——
三段全是「老师说得对」就是不合格，必须重写。

**篇幅**：每段 2—4 条。写得越短越要保证有观点；写得越长越容易退化成复述。

## 4. 「可复用资产」写法

固定在 `.mine` 之后，`<ul>` 列出，**每行一个可执行动作**。

| 要求 | 说明 |
|---|---|
| 动词开头 | ✅ 「把 … 做成模板」 ❌ 「关于模板」 |
| 带对象 | ✅ 「把老师给的 7 个 Prompt 收进 `prompts/` 目录」 |
| 可判断完成 | ✅ 「本周挑 3 个同行爆款，各拉 1 遍片」 |
| 条数 | **5—7 条**，多了说明没挑 |

**判定**：读者把这 5—7 条抄进待办，不需要回看正文就能执行。

## 5. 转写同音误记的处理（三原则）

1. **就近标注**：在首次出现处标 `〔疑为 XXX〕`，或在章末集中说明。
2. **正文不改写**：保留转写原样，**不做静默替换**。
3. **不确定就不下结论**：人名/产品名无法确认时，写「（转写不清，不作确定性表述）」。

**为什么**：二次输出的用户可能会去核对录音。改过的原话会让整份报告失去可信度。

### 误记词典（实测积累，持续补充）

| 转写出现 | 实际所指 | 判定依据 |
|---|---|---|
| 龙虾 / 路透 | 具备 Computer Use 的对话式 Agent | 上下文为「能操作浏览器」 |
| C 浪 2.0 | 可灵 Kling | 视频生成语境 |
| PPTV / EPTV / ETV / KTV / 0TV | **libtv**（liblib.tv） | 手册原文比对 |
| Work / Word / 沃克阿里 | **WorkBuddy** | 手册原文比对 |
| GPM / GTM | GTM | 营销语境 |
| 东区 | 东南亚 | 跨境语境 |
| 5.3 Flash | Claude 3.5 Sonnet / GPT-4o 一类 | 只标「一类」，**不作确定性表述** |
| 曾鸣 / 宗明 | 曾鸣教授 | 人名，括号补注 |
| GEO / 极优 / CEO | GEO（生成式引擎优化） | 上下文为搜索优化 |

> 遇到新误记，**先判据、后标注**：能靠手册/官网原文核实的，标注为确定；
> 只能靠语境的，加「疑为」；完全无法判断的，写「转写不清」。

## 6. 课件内部不一致的处理

**原则：原样保留 + 加说明，不统一、不修正。**

| 实测实例 | 处理 |
|---|---|
| 内容策略层「三天一小报五天一大报」（口述）vs「三天一小爆、两天一大爆」（课件） | 两者并列，加 `.note` 说明差异 |
| 内容形式「9 个」（口述）vs 11 个（课件分页） | 以课件 11 个为准，正文注明口述为 9 |
| MAGIC 公式的 M：「市场洞察」（五边形图）vs「挖掘需求」（分页） | 双列对照 |
| AI 视频成本「1.5 元/秒」（口述）vs「约 30 元」（纪要） | 两个口径都留，注明各自来源 |

> 课件内部矛盾是**最容易被「顺手统一」掉的**，而统一掉就等于伪造。
> 判定口诀：**你是记录者，不是编辑。矛盾本身也是信息。**

## 7. 遮挡 / 缺页的补齐

课件照片常被讲师范位遮挡。**补齐必须留痕**：

1. 优先找同一张 PPT 的**另一张留存照片**（重复拍摄的次要张）比对；
2. 补齐的文字在正文中显式标注：
   `（此处约 8 字被遮挡，据同一课件另一张留存照片补齐，括号内为整理者说明）`；
3. 无法补齐的写 `（此处被遮挡，未还原）` —— **不要猜**。

> 这也是「重复拍摄不全部丢弃」的理由：重复张往往是**遮挡的备份**。

## 8. 无录音场次的纪律（覆盖边界）

**只有讲义、没有录音/纪要/课件照片的场次 → 不做推测性还原。**

正确做法：在附录「覆盖边界说明」里写清——做了哪几场、哪几场没做、为什么没做。
交付说明里也要写一次。

> **不要用讲义去「写」一堂没听过的课。** 讲义的时序、重点、老师的临场判断都拿不到，
> 写出来的是「别人课程的摘要」，不是这一场的还原。

## 9. 章节架构模板（双场 / 多场通用）

```
00  一页纸速览 · 全局知识地图      ← 结论前置，7 条核心结论 + 1 张全景图
01  全景：本场课 × 模块分工        ← 时间轴 + 模块分工表
── 上半场 A1—An（蓝）  ──
── 下半场 B1—Bn（金）  ──
12  实战工具箱：Prompt · 框架 · 金句 · 术语 · 清单
附   附录：材料来源 · 覆盖边界 · 场次衔接 · 关键数字索引 · 照片总览
```

**每节固定四件套**：老师原话（金框）→ 课堂数据（青框）→ 我的总结（🦞 绿框）→ 可复用资产（紫虚框）。

**例外**：`00` / `01` / `附录` 不需要四档齐全（它们是导航与元信息）。

**分节粒度**：一节 = 一个完整主题（老师讲它大约 10—25 分钟），实测一场半天课切 6—8 节最舒服。
切太细会碎（每节凑不出总结），切太粗会闷（一屏看不到边界）。

## 10. 知识地图与一页纸速览

| 模块 | 规格 |
|---|---|
| **一页纸速览** | 顶部一句话结论 + 7 条核心结论卡片（`.grid.g2`，每条带一档 `.badge` 标注认知类型） |
| **全局知识地图** | 三栏：左列上半场节点（蓝）· 中间脊柱（5—6 阶抽象层级）· 右列下半场节点（金）；底部三格「全篇 N 节 / 框架 N 张 / 术语 N 条」 |
| **中部脊柱** | 把 A/B 两场的节点**抽象成一条递进链**（如：认知重塑 ▼ 判断标尺 ▼ 系统与体系 ▼ 方法论与洞察 ▼ 内容工程 ▼ 商业闭环） |

**判定标准**：学员只看「00 + 01 两屏」就能说出「这场课讲了哪几块、彼此什么关系」。

> **脊柱是灵魂**：它把两场串成**一条**路径，而不是两个并列的模块。
> 只做目录（列章节名）不叫知识地图。

## 11. 附录必备五项

| 项 | 内容 |
|---|---|
| **材料来源清单** | 每份材料的文件名 / 页数或字数 / 用途 |
| **覆盖边界说明** | 做了哪几场、哪几场没做、**为什么没做**（见 §8） |
| **场次衔接** | 与前后场的关系（如倒三角结构：Day1 技术 → Day2 业务 → Day3 顶层设计） |
| **关键数字索引表** | 全部量化结论汇总成一张可核查的表 |
| **照片总览** | 由 `image_map.json` 自动生成的按章节分组相册（见 photo-pipeline §7） |
