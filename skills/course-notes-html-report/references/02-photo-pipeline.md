# 课件照片处理规范

> 照片密集场次的核心工序，也是成品质量差别最大的地方。
> 配套脚本：`scripts/prep_images.py`（压缩管线）、`scripts/make_sheets.py`（索引拼图）。

---

## 1. 三种处理方案与决策阈值

| 方案 | 适用 | 代价 |
|---|---|---|
| 不嵌原图，只矢量重建 | 照片 **< 10 张** | 丢失现场感与原始格式 |
| 只嵌原图 | 照片 < 20 张 | 无结构，读者要自己看图 |
| **照片嵌入 + 矢量重建双轨制** ✅ | 照片 **> 30 张** | 体积增大（需压缩管线），但信息量与可检索性最好 |

**决策依据**：照片是课堂的「原始凭证」，矢量重建是「可检索的知识」。两者解决不同问题，**都要**。

> ⚠️ 早期版本曾主张「课件照片一律矢量重建、不嵌原图」——**在照片密集场次这是错的**。
> 单文件 base64 会把 20 MB 图片塞进正文，编辑器打不开、浏览器卡死；而目录式交付没有这个问题。

## 2. 索引拼图法（先压缩视角，再精读）⭐

**问题**：110 张照片逐张 Read = 110 次工具调用，极其昂贵且难以定位「哪张属于哪一节」。
**解法**：先用脚本压成若干张 3×3 索引拼图（每格带编号 + 时间戳标签），一次 Read 看 9 张，
12 次看完全部 → 建立「编号 ↔ 内容」映射 → 再对**核心框架图**（约 20 张）逐张精读原图。

### 拼图参数（实测可用）

| 参数 | 值 |
|---|---|
| 网格 | `COLS, ROWS = 3, 3`（9 格/张） |
| 单格宽 | `TILE_W = 470` |
| 单格高 | `TILE_H = int(TILE_W * 1050 / 1400)` = **352** |
| 间距 | `PAD = 6` |
| 标签条高 | `LABEL_H = 22` |
| 标签底色 | `(240,196,88)` 黄底 + 深字 `(20,20,20)` |
| 标签内容 | `pNNN  HH:MM:SS` |
| 字体 | `C:/Windows/Fonts/msyh.ttc` 17px |
| 整张尺寸 | **1434 × 1146** |
| 输出质量 | JPEG `quality=82` |

```python
# 核心循环（缩略自 scripts/make_sheets.py）
TILE_W, TILE_H = 470, int(470 * 1050 / 1400)
for s in range(math.ceil(len(shots) / 9)):
    chunk = shots[s*9:(s+1)*9]
    W = 3*(TILE_W+PAD)+PAD; H = 3*(TILE_H+LABEL_H+PAD)+PAD
    canvas = Image.new('RGB', (W, H), (18,18,20)); d = ImageDraw.Draw(canvas)
    for i, it in enumerate(chunk):
        r, c = divmod(i, 3)
        x = PAD + c*(TILE_W+PAD); y = PAD + r*(TILE_H+LABEL_H+PAD)
        canvas.paste(Image.open(f"images/{it['code']}.jpg").convert('RGB')
                     .resize((TILE_W, TILE_H), Image.LANCZOS), (x, y))
        d.rectangle([x, y+TILE_H, x+TILE_W, y+TILE_H+LABEL_H], fill=(240,196,88))
        d.text((x+5, y+TILE_H+2), f"{it['code']}  {it['time']}", fill=(20,20,20), font=font)
    canvas.save(f"sheets/sheet_{s+1:02d}.jpg", 'JPEG', quality=82)
```

**效率**：一次 Read 看 9 张 = 逐张读的 **9 倍**。105 张从 105 次调用降到 12 次。

### 标签必须带时间戳

照片文件名形如 `IMG_YYYYMMDD_HHMMSS.jpg`，**时间戳 = 讲课顺序**，
所以**照片编号顺序 = 课程顺序**。这就是「照片自动归位到对应章节」的依据。

后续在图注里直接写「10:45:13」这种坐标，比「第 N 张」有用得多——
读者能据此判断这段内容在课堂的哪个位置。

## 3. 去重规则

| 规则 | 说明 |
|---|---|
| 判据是**内容**不是文件名 | 同一页 PPT 被多次拍摄，文件名不同、内容相同 |
| 保留哪张 | **最清晰的一张**（分辨率高、无遮挡、无虚焦） |
| 记录剔除理由 | 在脚本里用注释写明「与 `pNNN`（时间戳）同页」，便于回溯 |
| 剔除率经验值 | 实测 110 → 105（**4.5%**）；**超过 15% 说明拍摄质量有问题，要在交付说明里提** |

```python
# 剔除表写法（DROP 集合 + 逐条注释）
DROP = {
    'IMG_20260915_104325.jpg',  # 与 102418「爆款的核心法则：以暴制暴」同页
    'IMG_20260915_104132.jpg',  # 与 104154「案例深挖 Liquid Death」同页
    ...
}
```

**剔除不是丢弃**：被剔除的照片仍保留在原始输入目录（**只读，不动**），只是不进报告。
**重复张是遮挡的备份**——正文补字时回头找它（见 content-restoration §7）。

## 4. 命名与编号

| 类型 | 编号规则 | 排序依据 |
|---|---|---|
| 课件照片 | `p001` — `pNNN`（3 位补零） | 文件名时间戳升序 |
| 手册截图 | `m001` — `mNNN` | 手册文件名数字前缀升序 |

**手册截图去重要注意**：源目录常存在「带扩展名 / 不带扩展名」的同一张图（内容完全相同）
→ 按数字前缀分组去重，**优先保留带扩展名的**：

```python
byno = {}
for f in sorted(os.listdir(SRC_MAN)):
    m = re.match(r'^(\d+)_', f)
    if m:
        k = m.group(1)
        if k not in byno or f.lower().endswith(('.png', '.jpg', '.jpeg')):
            byno[k] = f
```

> 编号一旦生成**不再变动**（正文引用、相册、验证脚本都依赖它）。
> 新增素材一律追加在末尾，不要插入中间。

## 5. 压缩双尺寸管线（核心参数）

| 用途 | 宽度 | 质量 | 参数 | 实测均值 |
|---|---|---|---|---|
| **大图**（灯箱 / 下载） | 1400px | 78 | `optimize=True, progressive=True` | **129 KB** |
| **缩略图**（网格 / 相册） | 560px | 72 | 同上 | **28.3 KB** |

- 只缩不放（`if im.width > W` 才 resize），避免小图被拉大模糊；
- 统一 `im.convert('RGB')`（消除 EXIF 方向与 CMYK / PNG 透明底问题）；
- 重采样一律 `Image.LANCZOS`；
- **体积预算**：132 张 → 大图 16.63 MB + 缩略图 3.64 MB ≈ **20.3 MB**（可接受上限约 **30 MB**）。

```python
FULL_W, FULL_Q = 1400, 78
THUMB_W, THUMB_Q = 560, 72

def save_pair(im, base):
    im = im.convert('RGB')
    o = im if im.width <= FULL_W else im.resize(
        (FULL_W, round(im.height*FULL_W/im.width)), Image.LANCZOS)
    o.save(f'images/{base}.jpg', 'JPEG', quality=FULL_Q, optimize=True, progressive=True)
    t = im if im.width <= THUMB_W else im.resize(
        (THUMB_W, round(im.height*THUMB_W/im.width)), Image.LANCZOS)
    t.save(f'images/t/{base}.jpg', 'JPEG', quality=THUMB_Q, optimize=True, progressive=True)
```

## 6. `image_map.json`（照片总表，构建与相册的唯一数据源）

```json
{
 "shots": [
  {"code":"p001","src":"IMG_20260915_094244.jpg","time":"09:42:44","w":1400,"h":1050}
 ],
 "manual":[
  {"code":"m001","src":"07_xxx.png","label":"libtv 一键拉片","w":1400,"h":900}
 ]
}
```

**必须由脚本生成，不要手写**——它是「交付资源 ↔ 正文引用」的唯一桥梁，
构建、相册、验证三个环节都读它。

## 7. 照片归位：三处呈现形态

| 形态 | 位置 | 数量 | 组件 |
|---|---|---|---|
| **① 正文配图** | 该章节正文中，紧贴对应段落 | 只挑该节最关键的 1—4 张 | `<div class="shots">` + `.shot`（带 `.cap`：编号 + 时间戳 + 一句说明） |
| **② 章末分组相册** | 每章末尾的折叠块 | 该章全部照片 | `<details class="gal">`，展开后才加载 |
| **③ 附录总览相册** | 附录 | 全部照片，**按章节分组** | 同上，由 `image_map.json` **自动生成** |

### 自动生成相册的算法

扫描所有分片，用**一次正则**同时匹配章节号 / 章节标题 / 照片编号，
记录每张照片**第一次被引用的章节** → 按该章节分组；
未被正文单独引用的照片归入「未在正文单独引用（相似页／重复拍摄）」组。

```python
pat = r'<section id="(s\d+)"|class="no">([^<]+)<|<h2>([\s\S]*?)</h2>|images/t/([pm]\d+)\.jpg'
```

> **好处**：以后增删章节或调整照片位置，相册自动跟着变，**不会与正文脱节**。
> **不要在正文里手写「共 132 张照片索引」**——必然与素材目录不同步。

### 构建脚本里的占位符机制

正文片段中只写 `<!--GALLERY:shots-->` 与 `<!--GALLERY:manual-->`，
`build_report.py` 在拼接时读 `image_map.json` 现场生成并替换。

**相册摘要要写清数量与时间范围**：
`现场课件照片 · 105 张 ｜ 09:42:44—11:56:42 ｜ 按章节分组，展开后才开始加载图片`

## 8. 双轨制：照片 + 矢量重建

| 轨道 | 载体 | 处理对象 | 规则 |
|---|---|---|---|
| **照片轨** | `<img>` + `images/` | 全部课件照片 | 原样呈现，配时间戳 |
| **矢量轨** | `<div class="kfig">` | **核心框架图**（约 20 张：六阶段 / 阶梯 / 闭环 / 公式 / 对照表） | 用 HTML 表格 / `.grid` / `.flow` / `.steps` / `.dl` **重建**，每个字段与课件原文一致 |

### `kfig` 的强制要求

1. 标题前自带「重建」标签（`::before{content:"重建"}`）—— **让读者知道这是重建不是截图**；
2. 重建内容与课件**逐字对齐**；同一张图有多个版本时用**双列对照**；
3. 需要时在 `kfig` 内加 `.note` 说明「与口述不一致」。

**怎么挑要重建的图**：表格型（对照/清单）、流程型（闭环/管道）、分层型（层级/阶梯）——
**结构化的图**值得重建；纯插画、实物照片不值得。

**判定标准**：一节课的核心框架图，**读者不打开照片也能读懂结构**。

## 9. 懒加载与性能约束

| 措施 | 实现 |
|---|---|
| 网格用缩略图 | `src="images/t/pNNN.jpg"`（28 KB 而非 129 KB） |
| 灯箱用大图 | `<a href="images/pNNN.jpg" data-zoom>`，**点击才请求** |
| 折叠相册延迟加载 | `<details>` **展开时**才把 `data-src` 提升为 `src` |
| 原生懒加载 | `loading="lazy"` + 显式 `width`/`height`（防布局跳动） |
| 相册不占首屏 | 首屏只加载正文配图 |

**验证断言**：`img[data-src]` 数量 > 0（证明懒加载存在），构建统计里打印「懒加载图片 N 张」。

## 10. 只读纪律（不可越线）

- `原始输入/` 下所有照片、PDF、手册：**只读**，禁止写入 / 重命名 / 移动 / 删除；
- 压缩产物一律输出到 `输出/<报告名>_<MMDD>/images/`；
- 照片若含**人名、联系方式、客户名、未公开数据**，
  交付说明里要提示「**公网共享前请确认可否外发**」。
