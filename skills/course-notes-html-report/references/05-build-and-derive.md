## 2. 分片构建（长报告必须这么做）

**问题**：7 万字报告写在单文件里，任何一次编辑都要重读全文，成本爆炸且容易截断。
**解法**：正文拆 `p1..pN.html`，**每片 2 节**（约 200—400 行），`build_report.py` 拼接。

| 分片 | 内容 |
|---|---|
| `p1.html` | `<div class="wrap">` 开始 + Hero + 目录 + 00 一页纸速览 + 01 全景 |
| `p2..pN.html` | 每片 2 节正文 |
| `pN+1.html` | 工具箱 + 附录 + `<footer>` + `</div>` 收尾 |

### 硬要求

1. `head.html` **只放** `<title>` + `<style>`（不含 `<head>` 标签本身，由构建脚本套壳）；
2. 分片开头**不写** `<div class="wrap">`，只在 `p1.html` 第 1 行开、最后一片末行关；
3. 分片顺序靠**文件名数字**排序（`p10` 要排在 `p9` 之后，用 `int()` 排序不要按字符串），
   不要靠人工维护列表；
4. 改样式只改 `head.html` 一处，**不要用行内样式**；
5. 片段边界必须**闭合**（`</section>`），但 `p1` 开 `<div class="wrap">`、最后一片关它。

### 构建脚本做的七件事

| # | 动作 |
|---|---|
| 1 | 按数字顺序读 `p1..pN.html` 拼接（可 `--frag N` 只构建到第 N 片做调试） |
| 2 | 读 `head.html`，套 `<!DOCTYPE html><html><head>…</head><body>` 外壳 |
| 3 | **注入灯箱单例 DOM**（放 `<body>` 起始处） |
| 4 | **替换相册占位符** `<!--GALLERY:shots-->` / `<!--GALLERY:manual-->`（读 `image_map.json` 现场生成） |
| 5 | **条件内联 Chart.js**（检测到 `<canvas>` 且文件存在才内联） |
| 6 | 追加 `TAIL_JS`（复制 / 灯箱 / 相册懒加载） |
| 7 | **标签配平自检 + 内容统计**，写到 `输出/<报告>_<MMDD>/index.html` |

### 构建期自检（内建，不要等到验证阶段）

```python
# 标签配平：抓明显漏闭合（这类错误不报错，但会让布局整体错乱）
PAIRS = ['div','section','table','ol','ul','dl','figure','header','footer','details',
         'aside','nav','article','main','span','a','p','h1','h2','h3','h4','h5',
         'pre','code','button','summary','b','strong','em','dt','dd']
# 开标签数 - 自闭合数 必须 == 闭标签数
```

> `<span>` / `<a>` / `<p>` 这类在 HTML5 里可以省略闭合标签，所以配平会有少量噪声——
> 用它**抓「差几十个」的粗错**，不要追求零差异。

**构建结束必须打印内容统计**（章节数 / 原话 / 数据 / 总结 / 资产 / Prompt / 复制按钮 / 照片 /
灯箱 / 框架重建 / 表格 / 相册 / 正文净字数）——这些数字后面验证阶段要复用，**必须同一套口径**。

## 3. 派生版：左侧常驻导航版

当用户说「把菜单放到左侧做导航栏」「随页面滚动固定、滚到哪高亮哪」「不要服务器、离线能开」时，
**不要重写报告**。两条路，按「本场是否已有导航版」选：

### 路 A（首次做）—— 从分片构建

加三个文件 + 一个新构建脚本，复用 `p1..pN`，正文片段零改动：

```
中间产物/<任务名>/
  sidebar.css      # 追加样式（插到 head.html 的 </style> 之前）
  sidebar.html     # 侧栏 DOM（插到 <body> 起始处）
  sidebar.js       # 交互（插到 </body> 之前）
  build_sidenav.py # 输出 <报告名>_<MMDD>_左侧导航版.html（不覆盖原文件）
```

### 路 B（系列场次第 2 场起）—— 从成品派生，先抽模板再用

比重新拼分片更稳、更快，且**保证两场观感一致**：

1. `extract_sidenav.py`：按文本标记从**上一场的导航版成品**里切出三段存到 `sidenav/`
   （`sidenav_css.html` / `sidenav_nav.html` / `sidenav_js.html`）。切分锚点：
   - 样式：找 `v2 追加样式` 开头的注释块到 `</style>`；
   - DOM：找 `<body class="has-side"` 之后到 `<div class="wrap">` 之前；
   - 脚本：找 `v2：左侧常驻导航交互` 所在的 `<script>` 整块。
2. `build_sidenav.py`：读**已构建好的主报告**，只做四件事 ——
   `</style>` 前追加样式块 · `<div class="wrap">` 前插侧栏 DOM · `</body>` 前追加脚本 ·
   `<body>` 加 `class="has-side" id="top"`。
3. **导航项从主报告的 `<nav class="toc">` 正则解析生成**
   （`<div class="am|pm"><b>序号</b><a href="#sN">标题</a>`），
   再按「速览 → A 组（蓝）→ B 组（金）→ 工具与参考」分组 ——
   这样导航项**永不与正文目录脱节**，也省掉手写十几行 HTML。
   **解析数不符预期就直接 `sys.exit(1)`，别静默生成半个导航。**

> **前置检查**：确认两场的 `:root` 变量名与 `.wrap` 宽度一致（同系列通常一致），否则样式会串色。
> **命名**：单文件场次 `<报告名>_<MMDD>_左侧导航版.html`；目录式场次主文件是 `index.html`，
> 导航版叫 `index_左侧导航版_<MMDD>.html`，与主报告**并存**，共用同一套 `images/`。

**派生后必查的回归项**：`href="#sN"` 里**不能残留上一场的锚点**（如新报告 17 节却出现 `#s18`）——
抽模板时最容易带过来；用 `re.findall(r'href="#s(\d+)"')` 比对最大 section 编号即可。

详细的交互契约见 `04-interaction-spec.md` §5；专项验证见 `06-verify-checklist.md` §3。

## 4. 归档版：HTML → Markdown（知识库用）

用户常在做完 HTML 后追加一句「再给我一份 markdown，进知识库存档，**确保内容一致**」。
**不要手工重写**——重写必然漂移。正确做法是写一个**解析式转换器**：
从同一批 HTML 片段出发，只做「结构映射」（视觉分块 → 语义块），正文一字不改，
然后**用子序列校验证明一致性**。

### 映射约定（供对齐）

| HTML | Markdown |
|---|---|
| `.quote` / `.quote.d` | 引用块 + 首行 `〔老师原话〕` / `〔课堂数据〕` |
| `.mine` / `.asset` | 引用块 + `🦞 ` / `📦 ` + **`.lb` 原文** |
| `.hl` | 引用块 + `🔍`(ok) / `ℹ️`(info) / `📌`(plain) + `〔.lb〕` |
| `p.note` | 段落前置 `※ ` |
| `.pbox` + `pre.prompt` | 标签行 + ```` ```text ```` 代码块 |
| `span.badge` | 行内代码 `` ` `` |
| `a[href^="#"]` | 纯文本（页内锚点在 md 里是死链） |
| `canvas` 图表 | **还原成数据表**（图表数值只存在于 JS，不属 HTML 正文，表格反而更可检索） |
| `h2/h3/h4/h5` | **1:1 保留原语义**（h2=章节 / h3=小节 / h4=小节内 / h5=卡片标题），不要为了「好看」降级 |

### 转换器的五个实现要点

1. `html.parser` 建节点树 → `block()` 返回**块列表**、`inline()` 返回行内字符串。
2. **`block()` 返回值类型必须统一为 list**：`render()` 返回字符串，若在 `block()` 里写
   `return render(...)`，调用方 `out.extend(str)` 会把整篇**按单字拆开**（一字一行），**且不报错**。
3. **另写 `plain()` 取纯文本**：`inline()` 会主动跳过 `.lb`（返回 `''`），
   所以块标签（📦 / 🦞 / 〔〕）**必须用 `plain()` 取**，否则标签全空。
4. **`render()` 要把连续行内节点攒进缓冲区再 flush**：text / `b` / `em` / `code` / `span` / `a` / `br`
   一律先进 buf，遇块级元素才 flush。否则「文本＋`<b>`＋文本」的块会被切成一行一段。
5. **遍历要下钻**：`<h1>` 在 `.hero-in` 里面，只遍历一层会把 h1 渲染两遍。

### 逐条必查的坑

- [ ] **装饰字符不能丢**：`.kspine` 的连接符在不同知识地图里分别是 `▼` / `×` / `÷`
      （**写死成 ▼ 就错**），`.flow` 的 `.arw` 是 `→`。这些是 HTML 里的真实字符，丢了子序列校验必然失败。
- [ ] **`.lb` 可能带副题**：如「我的总结 · 四步法的真正价值不在「四步」」。
      用固定文案覆盖标签 = 丢字，一律改用 `.lb` 原文。
- [ ] **行尾两个空格不可清理**：那是 Markdown 的硬换行标记，用来还原 `<br>`。
      收尾若做 `re.sub(r'[ \t]+\n', '\n', md)`，页脚 / 时间轴 / 键值块的换行会被全部抹平。
- [ ] **斜体不要叠**：小节副题里本就含 `<em>`，外层再套 `*...*` 会得到
      `**上半场 · 赵哲*　｜ …*`（强调错乱）。包斜体前先判断内部是否已含 `*`。
- [ ] **有且只有一处呈现性重排**：hero 的 kicker 在 HTML 中位于 `<h1>` 之前，
      MD 把 H1 提到最前（符合「文档以 h1 开头」的惯例）。
      **在验证脚本里显式对调该处后再比对**，并在交付说明里点明，不要偷偷放过。
- [ ] **`<head>` 会泄漏**：`<title>…</title>` 的文本会变成正文第一行。
      转换器里 `head/title/meta/link` 必须整体跳过。
- [ ] **`.st` / 目录项 / 带 `<em>`+`.badge` 的 `h5`** 如果用「带标记渲染」再外层包一层，
      会出现 `****00****` `[[标题](#s0)](#s0)` 这类畸形标记 —— **这几个位置改用纯文本抽取**。
