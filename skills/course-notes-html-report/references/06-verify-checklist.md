# 验证规范与交付发布

> 验证脚本在 `scripts/`（`verify_report.py` / `verify_md.py` / `verify_sidenav.py` /
> `probe_narrow.py` / `probe_overflow.py` / `verify_live.py`）。
> **全部可复跑**——交付说明里给出的结论必须能由脚本重现，不能只说「已检查」。

## 1. 五层验证

| 层 | 查什么 | 判定 | 失败即阻塞 |
|---|---|---|---|
| **L1 结构** | section id 无重复；所有站内链接都有落地章节；目录项覆盖全部章节且**顺序一致** | 全通过 | ✅ |
| **L2 资源** | 正文引用的图片**全部存在**；大图都有对应缩略图入口；存在懒加载标记 | 零缺失 | ✅ |
| **L3 一致** | Prompt 块数 == 复制按钮数；A1—Bn 与工具箱每节都有 `.mine` + `.asset` | 完全相等 | ✅ |
| **L4 渲染** | 无头 Chrome 1440px / 窄屏截图成功；整页 PDF 生成成功 | 图片 > 20 KB | ✅ |
| **L5 窄屏真视口** | iframe 定宽 360/390/480px：`scrollWidth == 视口宽`，**容器外**越界元素 0 | 全绿 | ✅ |

### 内容层另有三层自检（不靠脚本，靠人核）

1. 四档标注是否都在（页脚图例 + 附录声明）；
2. 转写误记是否**就近标注**、正文是否保持原样；
3. 附录是否写明**覆盖边界**（哪几场做了、哪几场没做、为什么）。

## 2. 派生版与归档版的额外验证

| 对象 | 验证方式 | 通过标准 |
|---|---|---|
| **左侧导航版** | ① 与主报告做**字节级比对**（从 `<div class="wrap">` 起）② scroll spy 逐节走查 ③ 原版文件字节数与 mtime 未变 | 正文完全相同；走查全命中；原版未动 |
| **Markdown 归档版** | HTML ↔ MD 结构计数逐项比对（章节 / 原话 / 数据 / 总结 / 资产 / 框架 / Prompt / 表格 / 图片） | 各项完全对上；丢失项单独列出 |
| **发布副本** | 正文区块逐字节一致；图片引用零缺失；外部依赖 0 | 三项全过 |

### 2.1 「正文零改动」的硬证据写法

交付前把新旧两版从 `<div class="wrap">` 起的字节流**逐字节比对**，报告「首个差异位置」——
若该位置正好是新增的 `<script>`，即证明正文 100% 未动。

**更强的写法（推荐）**：

```
① 断言 len(原正文) == len(新正文) and 原正文 == 新正文
② 断言「新版 style 块以原版 style 块为前缀」→ 证明是【追加而非改写】
③ 另加 9 项组件计数全部相等
   （section / 原话 / 数据 / 总结 / 资产 / 框架 / Prompt / 照片块 / 大图引用）
④ 断言原版文件的字节数与 mtime 未变
```

### 2.2 scroll spy 走查（用 `--dump-dom`，**不要用截图**）

做法：复制导航版 → 注入自测脚本 → 逐节 `window.scrollTo(0, top+40)` +
`dispatchEvent(new Event('scroll'))` → 等 150ms 读 `document.querySelector('a.snav.on')` →
跑完把 `documentElement` 换成纯结果文本（并移除全部 `script/style`，把 dump 体积压到 1 KB 内）
→ 再 `--dump-dom` 取回。

**断言**：「当前节 == 高亮项」且**任意时刻 `a.snav.on` 只有 1 个**。
走查前先 `documentElement.style.scrollBehavior='auto'` 关掉平滑滚动。

> 这是验证侧栏**最可靠**的手段：它跑的是页面自己的 spy 代码，不受渲染限制。

### 2.3 高亮配色的视觉确认（侧栏是 `position:fixed`，**不需要滚动**）

直接脚本给目标项加 `.on`（A 组 / B 组 / 中性各一张）再截首屏，就能确认三种配色。

> **逻辑交给走查、视觉交给置高亮截图，分开做** ——
> 这样正好绕开「无头 Chrome 滚动后截图空白」这个死结。

### 2.4 窄屏必须 iframe 定宽

除了横向溢出，还要断言**抽屉态本身**：
`aside` 的 `transform` 是 `translateX(-100%)`、`.sidenav-btn` 的 `display` 是 `flex`；
加 `body.nav-open` 后 `aside` 的 `left == 0`、遮罩 `opacity == 1` / `pointer-events == auto`。

> **只看「没溢出」会漏掉抽屉打不开这类硬故障。**

## 3. 线上验证（发布后，七步）

| 顺序 | 检查 | 方法 |
|---|---|---|
| 1 | DNS | **用 DoH，不用 `nslookup`**（本机 DNS 会追加搜索后缀，假解析）<br>`curl -H 'accept: application/dns-json' 'https://223.5.5.5/resolve?name=X&type=A'` 看 `Status`/`Answer` |
| 2 | 证书 | `openssl s_client -connect X:443 -servername X` + `x509 -noout -subject -issuer -dates` |
| 3 | **页面字节** | 拉线上 `index.html`，sha1 与本地发布副本**逐字节相同** |
| 4 | **全部图片** | 逐张下载 → 断言 ① 200 ② `startswith(b'\xff\xd8\xff')` 是 JPEG ③ 与本地**字节相同**（排掉截断与二次压缩） |
| 5 | 404 行为 | 请求不存在路径应返回 404 |
| 6 | 交叉抓取 | 换一条网络路径（如 WebFetch）确认能解析出真实正文与导航 |
| 7 | **浏览器实测截图** | 1440×1000 首屏应看到固定侧栏 + 高亮；1000px 下应收成侧栏把手 |

> ⚠️ **Chrome 截远端页失败 ≠ 站点挂了**。曾遇 `ERR_CONNECTION_CLOSED`（强制解析到正确 IP 也一样），
> 但同机访问 example.com / baidu.com 正常，隔几分钟重跑即恢复 → **瞬时网络抖动**。
> 正确顺序：**先 curl 拿状态码 + 交叉路径判定站点是否活着，再重试 Chrome 拿视觉证据。**

**图片全量核验脚本**：`verify_live.py`（并发 12 线程，264 张约 20 MB、十几秒跑完）。

## 5. 交付形态与并存规则

| 形态 | 文件名 | 用途 | 生成方式 |
|---|---|---|---|
| **基线** | `index.html` | 打开即读 | `build_report.py` |
| **派生：左侧导航版** | `index_左侧导航版_<MMDD>.html` | 长文档导航、滚动高亮 | `build_sidenav.py`（三段插入） |
| **归档：Markdown** | `课程要点_<MMDD>.md` | 投喂知识库、转 Word、二次编辑 | `build_md.py` |
| **交付说明** | `交付说明_<MMDD>.md` | 二次输出入口 | 手写 |
| （可选）**发布副本** | `输出/<报告名>_共享版_<MMDD>/` | 上线托管 | `prep_publish.py` |

**并存规则**：派生版**永不覆盖**基线；改新版不动旧版；交付说明里说明哪个是哪个。

**交付说明必备八节**：

1. 交付物清单（文件 / 规模 / 用途 / 打开方式）
2. 中间过程产物位置（脚本清单 + 各部分职责）
3. 质量自检结果表（可复跑的命令）
4. 阅读标注体系（四档解释）
5. 派生版说明（改了什么 / 没改什么 / 怎么验证的）
6. 覆盖边界（**先说清没做什么**）
7. 素材来源清单
8. 在线共享版（如有）：链接 / 渠道变更原因 / 副本差异 / 上线验证记录 / 已知边界

## 6. 发布流程（可选）

```
1) prep_publish.py 建发布副本目录
   ├─ index.html = 导航版改名，正文逐字节一致
   ├─ 仅追加 4 条不可见 OG/description 标签（微信分享预览用）
   └─ 全量复制 images/，自检「图片引用零缺失 + 外部依赖 0」
2) workbuddy_sites_deploy 发布（language=static，domainPrefix 必填）
   ├─ 工作区已有应用 → 会返回候选，必须【列候选 + 问一次 + 结束回合等答复】
   └─ 内容更新重发 → 带上 .wbapp_<appId>.genie 里的 appId，链接不变（domainPrefix 仍必填）
3) 按 §3 做线上验证
4) 告知管理入口：前往「设置—数据管理—应用」中管理
```

**渠道优先级**：内置 `workbuddy_sites_deploy`（发布为应用）> `html-deploy`（htmlcode.fun）。

**为什么内置排在前面**：课程报告是**目录式**的（HTML + 20 MB 图片），
内置发布支持整目录静态托管；而 `html-deploy` 只收**单个 HTML 文档**，
要么把 264 张图 base64 进 HTML（超 1 MB 就属于它自己声明的「不适用场景」），
要么发一个图全裂的版本。

**`htmlcode.fun` 已于 2026-09-15 确认整站停服**：

```
HTTP 402 + X-Vercel-Error: DEPLOYMENT_DISABLED
（根路径、所有 API、连官方指南页都返回 78 字节的 "Deployment Paused"）
```

判定方法：`curl -D - -o /dev/null https://www.htmlcode.fun/` 看响应头有没有
`X-Vercel-Error`。有就直接换渠道，**别在本地网络里找原因**。

**平台硬规则（必踩一次）**：工作区里已经有应用时，工具返回
`{"type":"sites_deploy_needs_app_selection","candidates":[…],"canCreateNew":true}`，
并且**要求把候选列全（名称 + appId）、只问一个问题、结束回合等答复**——
不能自己按目录名或名字相似度挑一个。用户答完再调用，且只能二选一：
`appId=<用户挑的那个>` 或 `createNewApp=true`。成功后**必须**告诉用户管理入口。

**其他参数要点**：

- `userAskedToPublish=true` —— **只有用户当轮明确说了「发布」才能设**；
- `domainPrefix=<英文短 slug>` —— **即使复用已有 appId 也必须给**，
  否则直接报 `domainPrefix is required`，白跑一次；
- appId 记在工作区根目录的 `.wbapp_<appId>.genie`（内含 `name` / `localDir` / `entryHtml`）。

**已知边界要写进交付说明**：链接是**公网可达**的，拿到链接的人都能打开（含报告内的课件照片）；
要收回就在「设置—数据管理—应用」里下线。改了内容要重新发一次。

> curl 在本机还要加 `--ssl-no-revoke`（否则 `schannel: CRYPT_E_REVOCATION_OFFLINE`），
> 且**不要 `-o /tmp/...`**（报 `(23) client returned ERROR on write`），写到项目目录里。
> Chrome `--screenshot` **只认绝对路径**。
