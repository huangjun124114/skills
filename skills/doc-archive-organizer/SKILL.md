# 文档归档整理与知识索引

针对「历史文档存档」的标准化处理流程。核心判断：**重复文件通常不是"复制多了"，而是"分类体系不成立"的表象**——先重构分类，再去重，顺序颠倒会导致问题复发。

## 适用场景

- 数百至数千份文档，目录层级深（>6 层）、命名混乱
- 存在大量跨目录重复文件
- 需要把"存得住"的文件库变成"找得到、用得上"的知识库

## 工作流（三轮，每轮结束都要用户确认）

### 第一轮：只读诊断（不修改任何文件）

1. **全量扫描** → 输出 CSV 清单（路径/大小/修改时间/层级）+ 目录统计 + 类型统计
2. **重复检测**：
   - 先按**体积分桶**缩小候选（通常能从 100% 降到 30%），再对候选做 MD5
   - 13GB / 5200 文件约 11 秒完成
3. **关键指标——跨目录重复占比**：
   - >80% → 根因是分类维度混乱，必须先重构分类
   - <30% → 单纯的复制问题，直接去重即可
4. **结构分析**：最深层级、自嵌套目录（`X\X`）、命名问题（空格/`(1)`/版本词/日期串）、遗留格式、时间分布
5. 输出诊断报告 + 分类建议 + 四级去重优先队列（P0 垃圾 / P1 完全重复 / P2 同名不同内容 / P3 同名跨目录）

### 第二轮：执行整理（S0–S5）

| 阶段 | 动作 | 要点 |
|---|---|---|
| S0 | 全量备份 | `robocopy /E /COPY:DAT /DCOPY:DAT`，**跨盘**；完成后必须比对文件数与目录数 |
| S1 | 清理系统垃圾 | `.DS_Store` / `.tmp` / `.bak` / `.ldb` / `__MACOSX` / `._*` |
| S2 | 建新目录骨架 | 一级按业务域（MECE），层级 ≤4 |
| S3 | 规则化搬迁 | 同盘 `shutil.move`；先 dry-run 生成计划并检视抽样，再 `--execute` |
| S4 | 重复归集 | **搬迁后重新扫描检测**（路径已变）；每份保留 1 个 |
| S5 | 压平 + 索引 | 清理空目录，生成全库索引 |

**铁律**：
- 每一步都提供 `--execute` 开关，默认 dry-run
- 全程**零物理删除**，一律移入 `_回收站_YYYYMMDD\`
- 每次移动写 `move_log.csv`（src/dst/status），可精确回滚

### 第三轮：知识索引（L1+L2+L3）

| 层 | 内容 | 生成方式 |
|---|---|---|
| L1 速查导航 | 分区卡片（路径/文件数/体积/一句话定位/关键词） | 全自动 |
| L2 检索地图 | 按主题 + 按实体双视角，各含涉及目录与代表文档完整路径 | 全自动（文件名语义匹配） |
| L3 知识卡片 | 读正文编译，带来源标注与交叉引用 | AI 编译，挑 5 个高价值主题试点 |

L2 是核心价值——按"我要解决什么问题"组织，而不是抄一遍目录树。

## 关键技术

### 分类规则引擎
有序规则表 `(关键词组, 目标一级, 目标二级, 目标三级)`，第一个命中生效。要点：
- 特殊类别（项目包、素材库）规则前置，保持完整性
- 给"容器词"设黑名单（`资料收集集合`、`过程产物`、`临时文件`…），压平时丢弃
- 清理连续重复段（`深圳\深圳` → `深圳`）
- 关键业务维度要**提级**为二级分类（如流程阶段"开盘前/后"），避免被层级截断丢失
- 目录深度上限按分类差异化（项目档案/流程库可放到 5 层）
- 必设 `TOP_FALLBACK`：根目录散件按所在顶层分区兜底，避免落入"待归档"

### 文档正文提取（无需额外装库）
| 格式 | 方案 |
|---|---|
| PPTX | `python-pptx` 遍历 `slide.shapes`，取 `text_frame.text` 与 table |
| PDF | `pdfplumber` 逐页 `extract_text()`，限制页数 |
| DOCX | `zipfile` 读 `word/document.xml` + `re.sub(r'<[^>]+>','',xml)`（**python-docx 未安装时的替代方案**） |
| XLSX | `zipfile` 读 `xl/sharedStrings.xml`，正则取 `<t>` |

已验证可用的库：`pdfplumber`、`python-pptx`、`PyMuPDF(fitz)`；缺失：`pypdf`、`python-docx`。

### 代表文档打分
`关键词命中数×2 + 体积分（>5MB +2 / >1MB +1）+ 年份新鲜度（≥2021 +1.5 / ≥2019 +0.5）`，取 Top 8。

## 踩坑记录

1. **沙箱禁止删除**：
   - `os.remove` / `os.rmdir` / `shutil.rmtree` 一律触发 `[safe-delete] SAFE_DELETE_FAIL_CLOSED windows-sandbox-recycle-bin-unavailable`
   - **跨盘 `shutil.move`（如 D: → `C:\...\Temp`）同样被拦截**——跨盘 move 本质是"复制+删除源"，被判定为删除
   - **同盘 `shutil.move` 可通过**（D: → D: 任意目录）
   - → 清理/删除的唯一可行路径：**同盘移入回收站目录**，再由用户在资源管理器手动删
   - 空目录同样处理：`shutil.move(empty_dir, recycle_dir)`
2. **CSV 写文件漏表头**：`csv.DictWriter` 必须显式调 `writeheader()`，否则读取时 `KeyError`。
3. **路径匹配偏差**：从目录清单复制的路径可能有出入（如 `IT规划项目` vs `IT项目规划项目`、多一层中间目录）。
   → 执行前用 `find -name "*关键词*"` 核实实际路径。
4. **大文件 Read 超限**：超过 20000 token 时用 `offset`/`limit` 分段读。
5. **Windows 中文路径**：Python 输出统一加 `sys.stdout.reconfigure(encoding='utf-8')`，并设 `PYTHONIOENCODING=utf-8`。
6. **robocopy 慢**：跨机械盘约 145 MB/分钟，13GB 需 1.5 小时；用 `du -sm` 观察大小稳定判断完成，比对文件数校验。

## 验收标准

- **数据守恒**：`整理后 + 回收站 + 移出部分 = 原始总数`，必须显式算给用户看
- 备份文件数与源完全一致
- 搬迁失败数 = 0
- 自嵌套目录残留 = 0

## 常见偏差要主动说明

- **目录数下降有限**：若优先保留原有子分类、只做压平，目录数可能只降 10%（如 706→641）。
  单文件目录占比高时要说明，把"小目录合并"作为可选项交给用户决定。
- **层级超标**：项目包、流程库这类结构有业务含义的分类，刻意放宽到 5 层，要说明原因。

## 收尾清理（用户要求「清理临时文件」时）

按三类分开处理，**不要擅自删安全兜底**：

| 类别 | 处理 |
|---|---|
| 中间/临时产物（扫描 CSV、dry-run 计划、编译底稿、日志、中间 JSON） | 清理 |
| 交付物（索引、报告、wiki 卡片）、回滚依据（move_log）、判定记录 | **保留** |
| 完整备份、回收站（重复副本/垃圾） | **询问用户**，不擅自删 |

交付的 HTML 索引要把数据**内嵌**为 JSON，做到自包含——这样清理掉中间 JSON 后索引仍可用。

## 输出规范

产出放 `.workbuddy/artifacts/`，明确区分**最终交付物**与**中间过程产物**（过程数据、脚本）。
最终交付文件名带日期版本号（`_MMDD`）。
