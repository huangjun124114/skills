# 日期推断（date-inference）

## 一、铁律

**禁止使用文件系统时间（mtime / ctime）推断日期。**
云盘同步、拷贝、恢复都会改写时间戳，且用户明确要求不用。唯一的例外是 ctime 审计（见 `verification-gates.md`），那是用于核对写入批次，不是用于推断拍摄日期。

## 二、信号优先级

按以下顺序依次尝试，命中即停止：

| 优先级 | 信号 | 标签 | 提取方式 |
|---|---|---|---|
| 1 | EXIF `DateTimeOriginal` | `exif` | Pillow `getexif()`，标签 `0x9003` / `0x9004` / `0x0132` |
| 2 | 文件名中的年月日 | `name_ymd` | `IMG_20211127_094726`、`微信图片_20220901180257` |
| 3 | 13 位毫秒时间戳 | `name_epoch_ms` | `mmexport1677923596872`、`Camera_XHS…` |
| 4 | XMP `photoshop:DateCreated` | `xmp` | 解析 XMP 包 |
| 5 | 文件夹名 `YYYY年MM月` | `folder` | 模式 A 场景下优先级最高，见下文 |
| 6 | iPhone 序号插值 | `interp` | `IMG_####` 序列号 k-NN，见第三节 |
| — | 无法推断 | `NONE` | 按规则排除，**不得猜测** |

**模式 A 调整**：若源区目录结构本身携带日期语义（如 `闺女/18-24个月/`、`2021年07月/`），将第 5 项（文件夹名）提到第 1 位。判断依据：目录名中是否出现年月数字。

## 三、序号插值（iPhone 连号照片）

无 EXIF 但文件名是 `IMG_####` 时，用同批已确定日期的照片做局部插值。

**参数（实测最优，勿随意放宽）**

```
WIN    = 150    # 序号窗口：只与序号差 ≤150 的邻居比较
MIN_K  = 3      # 最少邻居数，不足则放弃
AGREE  = 0.7    # 邻居日期一致率阈值，低于则放弃
```

**必须做留一验证（LOO）**：逐张隐藏、用其余照片推断、比对真实值。准确率 ≥ 95% 才允许启用插值，否则该批次按 `NONE` 排除。

实测参数扫描结果——放宽窗口会显著劣化，务必保持严格：

| 窗口 | LOO 准确率 |
|---|---|
| 150 | **98.4%** |
| 400 | 89.2% |
| 800 | 73.5% |

## 四、合理性闸门

```
YYYYMM 必须落在 201501 ~ 202612 之外则标记 OUT_OF_RANGE
```

命中 `OUT_OF_RANGE` 时保留原始值到 `ym_raw` 字段便于排查，但归类时按 `NONE` 处理。

## 五、视频日期（模式 A）

`mvhd` box：version 字节在 `i+4`，时间值从 `i+8` 起（`ver=0` 用 4 字节 `>I`，`ver=1` 用 8 字节 `>Q`），纪元为 1904-01-01。
**易错点**：把 `i+8` 误当作版本号会拿到完全错误的年份。

## 六、年龄推断（模式 A 辅助）

仅当文件名**显式**出现「X岁 / X个月」时启用，绝不作为通用兜底。

- **X个月**：年 = 出生年 + ⌊X/12⌋，月 = (X mod 12) + 1；月 > 12 则年 +1、月 = 1
- **X岁**：年 = 出生年 + X，月 = 01

## 七、覆盖度参考

6,763 张家庭照片的实测分布：

| 来源 | 张数 |
|---|---|
| EXIF | 2,879 |
| 文件名年月日 | 1,153 |
| 13 位时间戳 | 88~121 |
| XMP | 88 |
| 序号插值 | 106 |
| 无法推断（排除） | 101 |

覆盖率 97.7%。**剩下的 101 张必须排除，不得用 mtime 或年龄猜测。**

## 八、时间戳正则易错点

```
错误：r"(?<!\d)(1[5-9]\d{12})\d*"       # 多了一位，mmexport1677923596872 匹配不到
正确：r"(?<!\d)(1[5-9]\d{11})\d*"
```
