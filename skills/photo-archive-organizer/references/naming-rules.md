# 命名规则（naming-rules）

按作业模式选用不同模板。术语见 `terminology.md`。

## 一、模式 A：迁移合并

```
YYYYMM-事件[-来源]
```

- **YYYYMM**：年月。月份不可考时默认 `01`
- **事件**：事件描述，如 `ktv`、`桂林`、`元宵灯会`、`毕业视频`
- **来源**：**非必需项**，方括号表示可选。见下方「来源规则」

### 来源规则（重要）

1. **来源为非必需项。** 是否在文件夹名上体现来源，须**询问使用者**；未获确认时默认不追加。
2. **已知来源不重复追加。** `（AI整理）` 本身即一种来源标记——识别到它即视为来源已知，不再追加 `-帅哥`/`-闺女` 等任何额外后缀。
3. **保留源文件夹信息。** 模式 A 合并时主要做日期识别，已有的语义命名（事件名、来源标记）一律沿用，不推倒重来。

**来源后缀映射（默认家庭相册，仅在用户确认需要时才应用）**

| 原目录 | 目标目录 | 后缀 |
|---|---|---|
| 帅哥 | 合家欢 | `-帅哥` |
| 闺女 | 合家欢 | `-闺女` |

`我的照片`、`美女` 默认不合并、保持原样。
`全家福` 为语义化保留目录，不强制加年月前缀。

### 模式 B → 模式 A 的命名过渡

| 阶段 | 命名 | 说明 |
|---|---|---|
| B 产出 | `201809-动物园孔雀（AI整理）` | 事件名已明确，来源标记为 `AI整理` |
| A 合并后 | `201809-动物园孔雀（AI整理）` | **保持不变** |
| 反例 | ~~`201809-动物园孔雀-闺女`~~ | 不得覆盖已有的来源标记 |

### 语义识别的触发条件

模式 A **仅在文件夹名无法识别语义时**，才对图片内容做事件/场景识别。
凡已由模式 B 命名过的目录（含 `（AI整理）`），直接沿用其事件名，不做二次识别。

**示例**

| 原输入 | 推导 | 结果 |
|---|---|---|
| `帅哥/ktv/IMG_0083.MOV`（mvhd=2019-01） | 事件=ktv，日期=mvhd | `201901-ktv-帅哥` |
| `闺女/叶丽珍/…`（文件夹名） | 事件=叶丽珍 | `202002-叶丽珍-闺女` |
| `微信图片_20220901180257.jpg` | 文件名日期=202209 | `202209-…-来源` |
| `闺女/18-24个月/IMG.MOV` | 出生2019+18~24月 | `202007-18-24个月-闺女` |

## 二、模式 B：筛选归档

```
YYYYMM-事件名（AI整理）
```

- `（AI整理）` 为固定后缀，用于区分人工整理与机器整理的目录
- **事件名**必须由人命名（模型无法看图），命名的输入是联系表（缩略图 + 元数据标签）

**重名处理**：同一 `YYYYMM` 下出现同名事件时，追加事件 ID 区分，如 `201808-竹筏漂流-3（AI整理）`。禁止使用 `（AI整理）2` 这类无语义后缀。

## 三、命名归一化

将以下变体统一为 `YYYYMM-` 前缀：

- `YYYYMMDD…` → `YYYYMM-…`
- `YYYY-MM-…` / `YYYY_MM-…` → `YYYYMM-…`
- `YYYY+中文`（无连字符）→ `YYYY01-…`
- `YYYYMM+中文`（无连字符）→ `YYYYMM-…`

**漏网点**：`YYYYMM` 后直接跟中文且无连字符（如 `202401为良深圳湾`）需补 `(\d{6})(\D.*)` 模式，否则残留非规范目录。

## 四、扩展名修复（magic byte）

`ftyp` 容器必须看 brand，不可一律判为 mp4：

| brand | 扩展名 |
|---|---|
| `qt ` / `qt` | `.mov` |
| `mp42` / `isom` / `m4v` / `avc1` | `.mp4` |
| `heic` / `mif1` | `.heic` |

HEIC 解析需 Pillow 支持 HEIC 插件，缺失时降级跳过并记录，不得中断整批处理。
