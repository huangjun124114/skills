# 问数与分析工作流

## 1. 识别任务

开始识别前，为本任务建立新的 `taskId`，并按 `runtime-and-cache.md` 确认当前 MCP 连接、工具集合和实时 schema。不同用户任务即使问题相似，也不得复用同一个 `taskId` 或缓存。

| 类型 | 典型请求 | 处理方式 |
|---|---|---|
| 连接诊断 | “怎么连接”“工具看不到”“鉴权失败” | 先检查工具可见性和 list 探测 |
| 封闭问数 | 一个事实、一个数字、少量指标 | 最小查询，直接回答 |
| 参数不完整 | 时间、组织、项目、状态等缺失 | describe 后只追问影响结果的必要参数 |
| 开放分析 | 趋势、原因、对比、结构、异常 | 设计少量可验证查询，表格或短洞察 |
| 报告任务 | “形成报告/洞察说明/可导出成果” | 规划数据范围，生成自包含 HTML |

## 2. 动态选表

多连接环境先按 SKILL.md「业务路由」选定目标系统（出租/租赁 → 悠租云；卖/销售 → 云掌柜），再对选定连接调用 list。首次需要数据时调用当前会话在线发现的 `yzy_list_report_analyses`。同一任务内若准备复用 list 结果，先确认其落盘时间不超过30分钟，且当前连接和实时 schema 未变化。按以下证据排序：

1. `name` 与用户业务对象是否一致。
2. `purpose` 是否覆盖用户目标。
3. `sampleQuestions` 是否包含同类问题。
4. `statDimensions` 是否支持用户要求的维度。
5. `metricCodes` 是否包含所需指标。
6. `grain` 是否足以回答问题。

不要固化或记忆全局报表清单。开放、关闭或重新发布报表后，以本次 list 为准。

缓存不得跨任务使用。新任务必须重新 list，即使旧目录缓存仍在30分钟内。

候选报表有多个时：若其中一个明显满足全部条件，直接选；若选择会改变口径或结论，列出至多 3 个候选名称及差异，只问一个选择问题。

**目录为空时的兜底**：list 返回 `catalogState=NO_READY_REPORTS` 或无匹配报表时，不得直接回答"查不到"——依次检查其余启用连接（重新 list 并核对应用身份），全部为空才告知用户无报表，并注明已检查过哪些系统。报表编码等长字段一律从落盘文件/read-cache 解析，不从终端实时 stdout 读取（超长输出会被折行截断导致编码误读）。

## 3. 读取定义并定位参数

对选定报表调用 describe，建立以下映射：

- 用户业务术语 → `columns[].label/description/name`
- 用户指标术语 → `metrics[].name/code/caliber/sourceColumns`
- 结果列 → `columns[].name` 及允许的 SELECT、WHERE、GROUP BY、聚合能力
- 业务参数 → `parameters[].name/inputKind/required/defaultValue/dicCode`
- 字典显示值 → `dictionaries[dicCode]` 的编码
- 查询语法 → `sqlSubset`、`databaseType`、`databaseVersion`
- 查询边界 → `limits`

指标映射不存在或口径为空时，不自行补充行业公式。可以说明当前发布定义未提供可靠口径，并询问用户是否改用可用字段。

## 4. 最少追问

将必要澄清作为 analyze 之前的强制关卡。用户使用业务口语且 describe 中存在多个不同口径候选时，先提问并等待确认，再取数；不得先查询各候选的数值再决定口径。仅在下列情况追问：

- describe 声明必填参数且无可用默认值。
- 用户给出的时间、组织、项目或状态存在多个合理解释，并会改变答案。
- 用户术语可映射到多个口径不同的字段或指标。
- 用户要求同比/环比，但基期无法从请求或报表定义确定。

选定口径时，记录用户术语、候选指标、所选 `metrics[].caliber` 原文和选择理由。存在多个候选时，向用户展示口径差异与选择理由并取得确认；无法引用可靠口径或无法唯一确定时一律提问，不自行拍板。

禁止事后合理化：不得用“另一候选字段全为零”“疑似未回填”“数据异常”等未经验证的推测替代或跳过澄清。字段异常只允许如实标注并说明不确定性，不得用来论证所选口径或擅自更换指标。

保留用户原始术语和单位，不擅自替换套、间、份等计量对象。describe 的单位或统计粒度与用户表述不一致时，先确认对应关系；不得仅改标签、假定等价或自行换算。

一次合并询问所有必要项，优先提供 2–3 个清晰选项。以下无需追问的情形仅在口径与单位已明确、无上述歧义时适用：

- describe 已声明默认值，且用户没有覆盖它。
- 请求中的范围与唯一字段/字典值明确对应。
- 缺失信息只影响非必要的补充洞察。

## 5. 构造查询

遵循 describe 返回的真实能力：

1. `FROM` 只能是 `logicalTable`。
2. 只投影 `selectable=true` 的列。
3. WHERE 只使用 `filterable=true` 的列。
4. GROUP BY 只使用 `groupable=true` 的列。
5. 聚合只用于 `aggregatable=true` 且函数位于列和 `sqlSubset.allowedAggregates` 中的列。
6. `sensitive=true` 的列不得出现在 SELECT、GROUP BY、ORDER BY 或聚合中。
7. 只写单条 SELECT；禁止子查询、多语句、注释、DDL、DML，以及 describe 明确禁止的形态。
8. 用户值一律用 `:name` 命名绑定，并在 `bindings` 中提供 `{value,type}`。
9. 报表模板参数使用 `arguments`，元素结构为 `{name,label,kind,value,begin,end}`（六个字段均必填）：
   - `kind="single"`：只填 `value`，**`begin`/`end` 必须为空字符串 `""`**——同时提供会触发 `INVALID_ARGUMENT: single 参数不得同时提供 begin/end`；
   - `kind="range"`：用 `begin`/`end`（可单端，另一端留空字符串），`value` 留空字符串；
   - `name`/`kind` 取自 describe 的 `parameters`；日期值为 `YYYY-MM-DD`；字典参数取 `dictionaries` 中的编码。
10. 字典参数使用字典编码，不把展示文本当作编码。
11. `maxResultRows` 不超过 describe 的硬上限；预期会超限时先聚合或缩小范围。
12. 携带 describe 返回的 `analysisDefinitionVersion`。

优先用一条查询回答问题。只有当不同粒度、不同基期或无法在允许 SQL 子集中安全合并时，才拆分查询。

## 6. 调用预算

预置客户端的会话404有限恢复是有界例外，按 runtime-and-cache.md 执行并计入请求预算；不得在外层追加重试。

- 完成用户明确需求所需的 list、describe、analyze 不受“补充分析”限制，但仍应复用结果并减少重复调用。
- 禁止用循环轮询、暴力试参、逐报表或逐行调用工具。先使用聚合 SQL、批量参数、单次较宽结果或本地计算减少调用。
- 只有无法合并且调用总数能在执行前精确确定为 1–29 次时，才允许有限循环；执行前记录上限，禁止运行时追加、递归、嵌套循环或拆分批次规避 30 次边界。数量未知或达到 30 次及以上时停止执行并缩小任务范围。
- 非用户明确要求的趋势、同比、环比或异常补充，只能使用当前结果，或最多再调用 1–2 次即可得出结论。
- 非用户明确需求不得切换到新的逻辑表。
- 整个非必要补充过程不得超过 3 次接口调用。
- 达到边界后直接回答已获得的事实，不继续探索。

## 7. 解释结果

- 脚本返回紧凑摘要 + `fullOutputPath`（完整 JSON 落盘文件）时，**从落盘文件解析完整业务信封**（columns/rows/effectiveArguments 等），摘要仅用于快速判断状态；不要从可能被终端折行截断的实时 stdout 读取长字段。
- 按 `columns` 顺序解释每个 `rows` 数组。
- 优先使用结果列的 `label`、`unit`、`metricCode` 和 `sourceColumn`；缺失时回连本次 describe，禁止按 SQL 别名猜口径。
- 使用 `effectiveArguments` 说明实际生效的业务参数。
- `warnings` 非空时，把与结论相关的告警放在结果附近。
- `resultLimited=false` 仅表示服务端未截断；不要据此扩大用户查询的业务范围。
- 所有计算结论必须能由返回数据直接验证。简单加减、占比和变化率可以在本地计算，并写明公式；不要为非必要结论追加查询。
- 使用缓存结果时，在结论附近用一行通俗话说明数据获取时间、缓存是否在 30 分钟有效期内及是否已过期。时间水位不完整时放弃缓存并重新查询。
